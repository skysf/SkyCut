# 2026-10-29 损坏的 MCP 回答 id 让读线程退出

## 症状

冒烟小程序回合法 JSON 但 `id=[]` / `{}` 时，客户端打印 TypeError，等调用方仍只得到超时。布尔 id 也会被 Python 当数字，无法正确对应调用。

## 根因

`_read` 只核对外层对象，随后直接用 id 查 waiting 字典；列表 / 字典不能当键，TypeError 不在原有 ValueError / OSError 处理里。它属于 #274 的失败显式化遗漏，不是原付费脚本 120 秒超时的已证实根因。

## 修复

在取字典键之前核对 JSON-RPC id 只能是 string / number / null，明确排除 bool；不合规抛 ValueError，走统一 `_fail` 唤醒并清空所有等待者。只报告错误类型，不输出原始帧。

## 验证

假 helper 在初始化成功后依次模拟列表、对象与布尔 id。修复前 7 个测试中这三种子场景都因超时失败（列表 / 对象另有线程 TypeError），修复后 7 / 7 通过，waiting 为空。旧行为就是直接对照的反向验证。无 App、网络或付费调用。

## 教训 / 防回归

协议层要在哈希查找前核对字段类型；坏帧必须唤醒等待者，不能只让读线程退出。长期说明见 [GUI 冒烟](../testing/gui-smoke-testing.md)的日志与失败判读。
