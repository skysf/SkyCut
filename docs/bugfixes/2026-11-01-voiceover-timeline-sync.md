# 2026-11-01 换旁白之后画面、标题和字幕还在旧时间上

## 症状

真人 / 原声音换成克隆声音，旁白从约 107 秒变成约 93 秒。视频、上层画面、标题、形状与旧字幕仍按旧段落排列，
需要逐个挪、裁或变速。逐项调用时现有 linkage 又可能按主轨或旧声音来源再跟一次，字幕被压缩或错位。

## 根因

既有编辑入口处理单段或同类批量修改，没有“这些对象属于哪段旁白”的显式映射。
linkage 按画面 / 原素材时间决定跟随，适合剪辑动作，无法知道新声音里每句何时开口；等比缩旧字幕也推不出新的停顿和语速。
把各类单项工具串起来会反复提交 / 联动，后一步失败时前面已经落地，撤销也不能一次恢复。

## 修复

- 新增 `sync_voiceover` 本地任务入口：给连续旧段落范围、新旁白 id、可选旧旁白 id 和显式对象清单。
  复用原生媒体时长探测，绕过导入缓存，按实际新音频长度累计边界并顺延映射中的后续段落。
- `AIVoiceoverSyncPlan` 直接持有现有 `AIBatchEdit`；画面复用 `AIClipEditPlan` / `AIClipEdit`，
  文字 / 形状复用 `AIOverlayEdits`，完整候选才校验最终重叠。普通三个批量接口默认行为保持。
- 变速、裁切、末帧定格沿用已有模型与素材管线，超限在修改前明确失败；不新建合成器。
- 字幕复用本机转写和 `SubtitleCueWords` 字符对齐，比较键可折叠繁简体，原稿和身份完全保留。
  新词时间一次写进现有双轨编辑器，原文来源改为新声音，不缩放旧词时间。
- 全量准备成功且快照未过期后，唯一 `AIBatchEditTools.commit` 以 `alreadySettled` 采用完整候选，
  走已有快照采用 / 撤销路径，不再次磁吸或联动；不更改全局开关。一次撤销、一次预览请求。
- 复用 `AIJobs` / `get_job` / `cancel_job`；失败保留原音频，只重试同步，不请求付费生成。

## 验证

`scripts/check-voiceover-sync.sh` 使用实际 App 目标文件、合成 WAV 和视频，仅注入可控 ASR 词时间。
工程含 V1 / V2、文字、形状、旧 / 新声音和繁体字幕，分别验证短 / 长音频、裁切、原生抽帧转码、
最终冲突、过期拒绝、取消及整份工程一步撤销 / 重做。

- 整工程 84 项断言通过：20 秒的旧段落分别适配 10 秒 / 27 秒新声音，原始 10 秒起点在磁吸开着时仍保留；
  同时变长不会误判中间状态重叠，最终碰到未映射片段则整次失败。新旁白故意带过期的导入时长，结果仍按真实文件长度。
- 第二段字幕对齐失败不落前半份；第二个定格素材失败不插第一个，并清理本次新 PNG；ASR 期间用户编辑被保留。
- 反向验证：临时改回普通 perform（重复磁吸 / linkage）→ 7 项红；临时按旧字幕时间缩放 → 4 项红；
  临时关闭最终冲突校验 → 1 项红。每轮按原字节恢复生产源文件，最终 SHA-256 核对一致。
- 完整 MCP 2,869 项、Sky Studio 871 项及原旁白失败恢复的实际 App 对象检查通过；工具清单保持在既有 100,000 字符以内。
- 完整 App 构建与扫描守卫使用本次生产代码检查；真实克隆音频的听检 / 真窗口视觉回归按架构文档清单留待发版前。

实测开发中发现并纠正两处验收问题：不能把 PCM 单次 read 的帧数当总时长（4 秒文件该次读取只有约 3.994 秒），
改为复用原生文件时长探测；合成工程必须补齐全帧内素材的关键帧间隔元数据，否则后台优化媒体补标注会正确触发快照过期保护。
保护不放宽，通过构造完整工程隔离无关后台变化。

## 教训 / 防回归

显式段落同步是一份完整编辑计划，不能冒充几次独立的拖动让联动收尾猜第二遍。
音频时长、画面的相对位置、字幕的实际开口是三种时间依据，不能全部用一个比例代替。
长期参数、能力限制、生产接线与人工回归见 [按旁白段落同步时间线](../architecture/voiceover-timeline-sync.md)。
