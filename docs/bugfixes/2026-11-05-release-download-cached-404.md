# 2026-11-05 新下载包被上传前的 404 缓存挡住

## 症状

发布 SkyCut 0.18.57 时，上传 R2 返回成功，未带查询串的公开下载地址仍返回 404；
同一文件带新的查询串后返回 206，大小、类型和修改时间都表明对象已经在存储中。
旧的 0.18.47 下载入口在新包完成回读校验前没有切换。

## 根因

上传前为了检查版本文件名未被占用，访问了尚不存在的公开 URL。当前下载域名把这次
404 也缓存了：实际响应为 `CF-Cache-Status: HIT`、`Age: 108`、
`Cache-Control: max-age=14400`。上传 R2 不会让这个已缓存的缺失响应立刻消失。
现有 Pages 凭证未能列出该 zone，未执行清缓存，也不为这次发布扩大授权。

## 修复

改用包含完整 DMG SHA-256 前缀的不可变版本对象：
`SkyCut-0.18.57-32b9118d79e5-arm64.dmg`。只在上传后第一次访问公开 URL，完整下载
回读与本地固定签名包比较一致后，才更新个人站两条下载重定向。
不覆写旧版本文件、不清空全站缓存、不改变其他产品下载。

## 验证

新增发布专用 `scripts/check-release-download.py`，真实读取候选直链或固定入口，比较
HTTP 状态、最终域名、大小和 SHA-256。它在发布时跑，不让普通 PR 依赖未发布的包。

- 初次记录到的缓存 404 并不能稳定复现：后来同一地址从另一请求路径已返回正确包。
  这次调用没有变红，不能把它算反向验证。改用一个明确不存在的候选地址，确认真实
  HTTP 404 会让守卫非零退出；不为测试上传或改坏线上文件。
- 经旧的正式入口拿到 0.18.47 时，守卫因文件大小 / 内容不符而非零退出。
- 改回新的内容寻址地址时，完整读取 33,105,257 字节，SHA-256 与本地包一致，守卫通过。
- 正式入口切换后必须再用默认入口执行守卫，确认用户路径也拿到相同字节；结果以本次
  发布的实际检查为准，不把上传成功或局部 Range 请求当成完成。

## 教训 / 防回归

上传前的“只读检查”也会改变 CDN 缓存状态。版本化对象的存在检查走存储 API，
公开 URL 留到上传后再读；每次发布保留完整下载校验，并在它通过后才切入口。
长期合同和人工发布回归清单见 [公开下载发布](../build/build-and-packaging.md#公开下载发布)。
