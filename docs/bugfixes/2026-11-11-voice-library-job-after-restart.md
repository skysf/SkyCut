# 2026-11-11 SkyCut 重启之后不记得在建的声音库那一单：再点头本机账多记一笔，重启前那一笔也没人结

## 症状

[声音库](../architecture/voice-library.md)第十节末尾记着的「已知不足」，用户 2026-11-11 早上要修：

- 用自己的声音配旁白，点头建 MiniMax 版（一次性费用 377.6 积分）。**还没建完 SkyCut 就退出了**（⌘Q、崩溃、关机）。
- 再打开，让 AI 再配一次：AI 又问一遍价；点头之后本机的每日积分账上**这一笔记了两次**（755.2）。Sky Studio 那边只扣一次
  （同一个声音 + 语言开着的建单，不管 idempotency_key 是什么都回原来那一单：202、同一个 `job_id`）。当天的额度白白少掉一笔，
  第二天清零。
- 读代码时另外查出来的：**重启前那一笔从此没人结**。它一直按报价的上限留在当天的账上：做完了不按实收换（MiniMax 设计上限 760、
  实扣 751.4，多 8.6），服务器上没做成、钱退了的也不退。

一次运行之内早就没事了：#375（[设计声音连按](2026-11-11-design-voice-ordered-twice.md)）让同一件事只开一单、过闸之前先看在建的。

## 根因

**账在盘上，单只在内存里。** 一次性费用点过头那一刻，`SkyStudioJobGate` 就把报价记进本机的账（`SkyStudioSpendStore` →
UserDefaults `SrtFlow.skystudio.creditLedger.v1`）。这一笔之后怎么结（做完按实收换、没做成退回）挂在 `SkyStudioVoiceLibraryJob` 这个
对象上。「同一件事开着的那一单」也只在内存里：`SkyStudioVoiceLibraryJob.open` 和 `AIJobs`。SkyCut 一退出，账还在，单没了：

1. **重启前那笔预留**：没有任何东西再去问 `GET /jobs/{id}`，`SkyStudioHeldCredits` 的结账、退回永远不会跑。那一笔照报价的上限
   一直算花了，挂在那一天（账按天记、只看今天，所以第二天才不再挡额度）。这是第二条漏账的路。
2. **重启后再点头**：建 MiniMax 版的两个入口（`SkyStudioVoiceOneTimeStep`、`SkyStudioVoiceFallbackFee`）过闸之前看
   `SkyStudioVoiceLibraryJob.running(identity)`，看到的是空的。于是又问一遍价（待答的确认码也在内存里），点头之后再记一笔、
   起一个新任务、用新的 idempotency_key 再交。服务器回原来那一单、只扣一次，本机这一单做完照样 `settle`：一笔钱记成两笔。

**设计**不会这样：AI 每次设计都是一份新报价、一个新 key，重启后再设计就是另一单，服务器照扣；对话框里那份报价重启后也没了。
设计只有第 1 条（重启前那一笔没人结）。**变声（`change_voice`）**也没有第 2 条：结果不明不重交，重启后再变是另一单（新 key、
服务器照扣）。第 1 条它和 upscale、生成一样有（一直写在第十一节的已知不足里：没有恢复记录），这次不改。

## 修复

**在建的一次性收费单落盘，重启之后接着跟到底，一单只结一次。** 长期约束写进 [声音库](../architecture/voice-library.md)第十节第 11 条。

- **新文件 `SkyStudioVoiceLibraryOrders.swift`**：在建的设计 / 建 MiniMax 版每单一条，按它的 idempotency_key 记在 UserDefaults
  `SrtFlow.skystudio.voiceLibraryOrders.v1`。一条记：种类、Key 的 SHA-256（只拿同一把 Key 跟，不存 Key）、请求、预留了多少、
  记在哪一天、受理了的任务号、做完时给 AI 的下一步。全部记录是一个键，一次写盘。
  - `resume(key:api:)`：这把 Key 名下、这次运行里还没人跟、有任务号的那几单，各起一个只 GET 的任务（`SkyStudioJobRun.resume`，
    旁白和角色的恢复早就在用），按原来那一笔结账。两天以前的记录丢掉，账不动（早过了那一天的额度）；别的 Key 的记录留给那把 Key。
  - `accept`：受理了就记下任务号。同一件事早先还有一条没结的（交的回答丢了、没有任务号；或者就是这个任务号），在同一次写盘里
    并进来：早先那一笔归这一单结，这一单自己那一笔退回。这就是「202 回的同一个 `job_id` 要认得出来」。
  - `unresolved`：哪些结局算服务器上还没完（问不到、等满 5 小时、停不下来、交的回答丢了）。这些留着记录，下次接着跟、那时再结；
    服务器给了结局的（做完、没做成、退了、找不到这一单）删记录、改账。
- **`SkyStudioVoiceLibraryJob`**：`start()` 起手先 `resume`（最后一道），再看 `running(identity)`；交之前存记录。
  `follow()` 是接着跟的那一种：不另存记录、只 GET，没做成时按种类说下一步（起它的那次调用早没了）。有结局时**先删记录再改账**。
  受理那一刻（`remember`）调 `accept`，并进来就把自己那一笔退回、改按早先那一笔结。
- **什么时候接着跟**：`SkyStudioAccount` 读到 Key 的那一刻（启动、回到 SkyCut、每小时、用户点了 Allow，和长期授权的补记同一处）。
  建 MiniMax 版的两个入口在看「已经在建」之前也调一次：启动那一步可能还没走到，比如新构建的钥匙串要授权。
- **`SkyStudioHeldCredits.settle`**：实收记在预留的那一天，不再记到结账那一天。Sky Studio 交的时候就扣了；
  第二天早上才接着跟完的单，不该挤占今天的额度。这条对 upscale、生成、变声一样，跨零点的单从此也不挪日子。

**为什么这样修、没有「账按 job_id 记」**：任务号要等交上去才有，可是 AI 在交之前就要问用户。按 job_id 去重只能在钱记了两笔
之后再退一笔，拦不住第二遍问价；没人再点头时，重启前那一笔还是没人结。账本是按天的合计（「只记数字，不记内容」），把每一单的
身份塞进去要改它和所有调用方。现在只把几条在建的单落盘，跟它们用的是一次运行之内那一套（同一个结账、退回、「只开一单」）。
`accept` 的并单补上了最后一个洞（交的回答丢了）。不学官方原创那样用带锁的文件存回执：记录很小、和账在同一个 UserDefaults 域里，
写盘的顺序保证出事时只会多算（先存记录再交、先删记录再改账、先写并单再退那一笔）。

**没做的**：交的回答丢了的那一单本机跟不了，同一件事再来时会再问一次价（账在受理时并成一笔）。没人再来的话，那一笔照上限留在
那一天。变声、upscale、生成重启前那一笔的结账不在这次范围里。

## 教训 / 防回归

1. **账在盘上，它要结的那一单也得在盘上。** 「一次运行之内只开一单」只管内存。凡是先记账、后结账的活，重启会把这两样拆开：
   账留着，单没了。以后再加一种先预留后结算的收费活，起手就问：SkyCut 退出了，这一笔谁来结？
2. **能去重的要在问用户之前去重。** 按任务号去重来得太晚：任务号要交上去才有，第二遍价那时已经问过了。在建的单落盘，
   问之前就认得出来。
3. **写盘的顺序决定出事时错向哪边**：先存记录再交，先删记录再改账。中间出事只会多算一笔，不会结两次、不会少算。
4. **检查的隔离不能靠「同一时间只有我在跑」**：几个会话会同时跑同一项检查。共用的 UserDefaults 域、临时目录、端口，每次运行
   要各用各的。
