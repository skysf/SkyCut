# 2026-11-04 查原任务时未核对回答中的任务号

## 症状

官方恢复路径复审发现：请求 `GET /jobs/A` 若异常收到 `job_id=B`，运行器会先把 B 的身份和账务
报告给调用方，随后持久回执才拒绝更换任务号。磁盘守卫仍在，但内存任务号和本机账务可能先被污染。
这是构造异常回答发现的边界，未观察到真实服务串单或实收错误。

## 根因

API 层只解析状态，未比对返回任务号与 URL 中请求的原任务号。后续进度与结算回调信任解析结果，
持久回执中的不可换号校验太晚，不能保护此前已经发生的内存副作用。

## 修复

`SkyStudioAPI.job` 在返回状态前校验任务号一致。错号回答作为损坏回答拒绝，不进入任务进度、账务、
下载或回执；正常轮询、明确原单恢复和提交错误携带任务号后的恢复共用这个边界。

## 验证

专项 1,419 项通过。假 HTTP 覆盖请求 A 却回答 B，恢复 / 正常轮询 / 提交错误后查单均拒绝 B
及其账务，正常相同任务号仍通过。隔离副本撤掉 API 身份校验后 9 项实际失败；真实工作树保留修复。
后台 MCP 与全量结果记入 [实施报告](../reports/2026-11-04-official-film-client.md)，未执行步骤不计为通过。

## 教训 / 防回归

恢复不是“拿到任意有效 JSON”。响应身份必须与原请求匹配，并在所有进度和账务副作用之前验证。
长期规则见 [Sky Studio 任务](../architecture/sky-studio-jobs.md)。
