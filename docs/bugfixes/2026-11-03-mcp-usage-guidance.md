# 2026-11-03 MCP 说明缺最小示例，结果提示还写着不存在的参数

## 症状

批量工具只说“读单项工具”，旁白同步、成片检查和快速审阅的入口难从真实需求直接找到。
准备隔离测试夹具时，字号误写 `size`，被参数核对正确拒绝；真实 `add_clips` 结果却建议
`edit_clip (end)`，而这个工具只有 `source_out`，照做同样会整次拒绝。
没有把测试脚本的错误称作 Codex 的错误，也没有凭清单存在声称自然语言选择已通过。

## 根因

目录给了工具名，未充分给需求对应关系；缺少经过实际 schema 校验的 JSON 示例。
结果中的旧“下一步”文字没有跟着参数合同更新。加入示例时还必须同时满足前 512 字和清单总量，
不能把关键行为挤到截断位置之后。

## 修复

- 统一目录保持简短，前 512 字包含批量编辑、旁白同步、成片检查、审阅导出。
- 三个批量工具、`sync_voiceover`、`inspect_video` 和 `export_video` 各给最小 JSON 示例；身份是明确标出的占位，先读当前工程取 id。
- 区分已有录音与生成旁白、源素材分析与混音成片检查；等待任务、失败复用音频、不改正式设置等约束写在对应工具。
- 声音超出画面的提示改用真实的 `source_out` / `fade_out`，更换旁白则指向同步工具。
- 示例按生产 schema 验名字、必填、类型、枚举和范围；结果提示有接线扫描，长期合同进入
  [AI 接口](../architecture/ai-control-mcp.md)与[MCP 功能发现](../architecture/mcp-discovery.md)。

  全部参数 schema 和六个重点工具定义与真实自然语言实测版本逐项相同。最后只补回了 `get_status` 的云端任务分组文字。
- 反向验证：恢复旧批量说明，三个工具缺示例的守卫变红（3 / 3,111）；恢复旧 `end` 提示，生产接线扫描变红。
  恢复被压缩的旧文字后，完整 JSON 超限，新外层预算守卫变红（1 / 3,129），旧的逐工具相加口径仍未超限。
- 首轮本地 `check-all`：81 项通过、1 项分组说明扫描失败；补回原有说明后，两条相关单项扫描与完整 `check-guards` 都通过。
  最终完整重跑为 **82 项通过、0 项失败**（含 3,129 项 MCP 检查）；没有把首轮称作全绿。合并仍以远端 `check-all` 为准。
- 真实 Codex CLI 0.166.0、用户默认 GPT-6.1-Sol / max：四条请求均实际完成。一次 `set_texts` 改两处标题；
  `sync_voiceover` 把 4 秒画面 / 标题同步到实际 2.443492 秒，样式和取景不变；`inspect_video` 完成且时间线不变；
  审阅导出实际为硬件 / AAC128 / 720p 上限，640×640 源保持 640×640，导出偏好前后相同。
- 两个额外的 `transcribe language=auto` 任务确实失败；明确告知录音为英语后，同一 Codex 对话用 `language=en`
  重试，两份均返回 `done` / `en_US`。不把自动识别失败算成成功，也没有用这批无字幕夹具声称逐词字幕对齐已验证。
  所有场景用独立合成工程和回环假账号，没有 Sky Studio 付费生成。

## 教训 / 防回归

名字出现在清单里，不等于调用方知道何时使用。最小示例必须能按当前参数合同通过，
关键行为要在客户端实际可见的前部；“下一步”结果里的参数名也属于接口。
