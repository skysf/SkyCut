# 2026-11-11 官网首页在手机和 iPad 上版面全乱：平板 / 手机规则排到了基础规则前面

## 症状

main（3329c3d）构建出来的首页，在 390 宽的手机上首屏还是左右两栏：标题 60 px 顶到右边、
副标题挤成一条、两个按钮被截掉一半、3D 场景按桌面的 560 高摆、底部三个标签溢出；834 宽的 iPad
同样是两栏。文档页、隐私页用同一套样式，首页以下的平台卡片、常见问题、邮件登记也都没有换成窄屏排法。
桌面 1440 正常。

没有上线：发现时 skycut.app 还是当天早上的旧构建（一个 `main-*.css`）。再部署一次 main 就会带上去。

## 根因

- 模板按 `base → home → responsive → showcases → pricing` 的顺序挂样式表，`responsive.css` 里放着
  **所有**页面的平板 / 手机规则，包括首页那一大半。它靠「排在 `home.css` 后面」才盖得住 `home.css`
  里同样选择器的基础规则（特异性一样，后来的赢）。
- 构建并不保留这个顺序。Vite 按「哪些页面共用」把样式表分块：2026-11-11 文章栏目（#392）给文章页
  挂了 `base + responsive + guides`，于是所有页面共用的 `base + responsive` 成了一块（`main-*.css`），
  首页、文档、隐私独有的 `home + showcases + pricing` 成了另一块（`pricing-*.css`），页面先加载前者。
  结果变成 `base → responsive → home → …`，首页的平板 / 手机规则全排在它们要覆盖的规则前面，一条都不生效。
- 之前一直没事，只是因为所有页面挂的是同一组样式表、构建出来只有一块。「顺序对」是碰巧，不是合同。
- 为什么没人发现：CI 里没有任何一项在手机宽度下看版面；#392、#393 和首屏 3D 的 #395 合并时都只看了
  桌面和各自关心的东西。#395 合入 main 之后跑过一遍浏览器检查，手机和 iPad 那几格全绿 ——
  那些格子只看场景显示的是静图还是实时画面、版面框在四种状态下一不一样，不看版面本身对不对。

## 修复

- 首页自己的平板 / 手机规则（84 条）从 `responsive.css` 搬到 `home.css` 末尾，紧跟在它们覆盖的规则后面；
  `responsive.css` 只留 `base.css` 管的东西（页眉、容器、文档页、页脚，30 条），并在文件头写明。
  `showcases.css`、`pricing.css`、`guides.css` 本来就各带各的媒体查询。这样不管构建怎么分块、谁先加载，
  覆盖规则都在基础规则后面。页面的 HTML 没变（`npm run stamp:pages` 没有页面要改日期）。
- 没有选「让文章页也挂全套样式表」或 `cssCodeSplit: false`：那只是让顺序重新碰巧对上，
  下一次哪种页面换一组样式表还会再坏。

## 验证

- `tests/css-cascade.test.mjs`（CI）：`responsive.css` 里的选择器不许同时出现在页面自己的样式表里；
  按模板顺序和按构建实际用的顺序（共用的一对在前）排，都不许有覆盖规则排在基础规则前面。
  未修复时两条都红（`.hero`、`.hero h1`… 共 34 个选择器两边都有，按构建的顺序有 65 处覆盖规则排在前面），修复后绿。
- `npm run check:seo`（CI，在构建之后）：读每个构建出来的页面实际挂的样式块，按加载顺序核对同一个
  选择器 + 属性的带条件规则没有排在不带条件的前面。未修复的构建退出码 1，报
  `.hero { grid-template-columns }: the @media (width<=1150px) override in /assets/main-….css loads before the base rule in /assets/pricing-….css`
  等几十条；修复后 53 个页面全过。
- `scripts/check-hero-browsers.mjs`（手动、无头）每一格多看一条版面哨兵：桌面首屏两栏、iPad 和手机一栏。
  换回未修复的样式，Chromium 的 33 项里 iPad 和手机 8 格全红（`2-column hero`）；修复后三个内核 63 项全过。
- 无头截图：390 × 844 首屏一栏、标题 42.9 px、按钮上下排；834 × 1112 一栏、标题 76 px；1440 两栏不变。
- 网站测试 114 项、构建、`scripts/check-local.sh` 通过。全程无头，没有部署。

## 教训 / 防回归

- **样式表之间的先后不是合同。** 构建按共用关系分块，挂的顺序会被打乱。每份样式表自带自己的媒体查询，
  `responsive.css` 只管 `base.css` 的东西 —— 写进了
  [SkyCut 官网](../architecture/skycut-website.md)「样式表的先后」。
- 给某一类页面换一组样式表（新栏目、新页面类型）之后，看一眼**别的**页面在手机宽度下的样子：
  分块是全站一起算的，改的是别人的加载顺序。
- 一项检查全绿，只说明它看的那件事没坏。场景的检查不看版面，所以加了版面哨兵；
  合并 main 之后要重新看手机和 iPad 的整页截图，不能只跑针对自己改动的检查。
