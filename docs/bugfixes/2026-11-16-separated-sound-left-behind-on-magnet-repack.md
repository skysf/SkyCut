# 2026-11-16 J / L 切的声音在磁吸重排之后和自己的画面错开

## 症状

做「声音过切点」（set_transition 的 sound，[声音怎么过一刀](../architecture/cut-sound.md)）时，在自检里先把会用到的后续改动走了一遍，撞出来的
（没有用户报，按代码推出、自检复现）：

- 磁吸开着、联动开着（都是常见设置）。镜头 B 的声音分到了音频轨上、往前伸了半秒（J 切：下一场的声音先进来），伸在前一个镜头 A 的底下。
- 把 A 拖到最后（换镜头顺序）：磁吸把 B 往前排了 4 秒，**B 的声音一动不动**，和 B 的画面错开整整 4 秒。
- 只把 A 的尾巴裁短 0.25 秒：B 被排上来 0.25 秒，B 的声音还在原地，错开 0.25 秒。
- 删掉第一个镜头 A：B 排到 0，它的声音跟着前移，可伸到 0 之前的那半秒被夹在 0 —— 整段声音晚了半秒。
- 上层轨的画面自己分出去的声音拖到隔壁主轨块底下（L 切），隔壁那块挪了，声音同样留在原地。

AI 的 `add_clips sound=separate` + `edit_clip alone`（2026-10-14 起的 J / L 切）一直有同样的问题，只是用得少；声音过切点一次能做几十刀，非修不可。

## 根因

1. **联动按「底下压着哪几段主轨块」判跟不跟**（[联动](../architecture/timeline-linkage.md)规矩 2、3）：完全落在一段里的跟着它；跨两段的，
   底下的画面**全部**挪同一个量才跟，否则不动。J / L 切的声音正好跨在两段上：自己那段被排挪了，隔壁那段没挪（或挪了别的量）→ 不动。
   对配乐、跨段的字幕这条规矩是对的（没有正确答案），对「画面自己的声音」是错的：它只属于自己那段画面。文档开头写着显式的链接组
   「照旧，而且更强（拉开了也跟）」，实现里却没有这一条 —— 拖动、裁切、删除时伙伴一起动，排挪（磁吸、ripple 之外的连带移动）时没有。
2. **挪到时间线开头之前的一律夹在 0**（`Plan.take` 的 `max(0, …)`）：文字、形状没有源时间，夹一下无所谓；段有源时间，夹在 0 等于整段
   往后错开。

## 修复

- **联动规矩 13**（`LinkagePartnerSound`，`VideoEditTimelineLinkage.swift`）：音频轨上一段声音如果是某段画面自己分出去的（同一个链接组、
  同一个文件、「源 ↔ 时间线」换算对得上），联动收尾时按**那段画面**的换算挪了多少挪；画面被真删就删、不是真删就留着；画面变速、换文件、
  或者换算对不上（被单独挪过的声音）照老规矩。上层轨的画面没被这次操作碰过时，声音和画面拿同一份结果。钩子还是 `followMain` 那一处
  （规则只在 `perform` / `liveApply` 收尾一处，没开第二个入口）。
- **挪到 0 之前的段裁掉头**（`EditClip.moveForLinkage`）：入点跟着挪、头上的渐入减掉裁去的那么多，换算不变；整段都在 0 之前（少见）照旧夹在 0。
  文字、形状、滤镜照旧夹在 0。

## 验证

  每一样都断言声音和自己的画面对得上；换算对不上的声音照老规矩留在原地（对照）。原有的联动各组（1f–1i）全绿，682 项。
- `scripts/check-mcp.sh` 的声音过切点检查（`checks/MCP/CutSoundLevelChecks.swift`）里「先进 12 帧之后删掉第一个镜头」一条。
- **反向验证**（2026-11-16）：撤掉规矩 13（`picture(of:)` 永远不认）、撤掉裁头（照旧夹在 0），第 1j 组红 8 项（重排 2、裁隔壁 2、删第一个镜头 3、
  上层轨 1），对照那一条照旧绿；恢复后全绿。

## 教训 / 防回归

- 「跟着画面走、不跟 id」是给**压在画面上的别的东西**定的；一段画面自己的声音本来就是那段画面的一部分，跟着 id（链接组）才对。加新的
  「从画面里拆出来的东西」时先问：它属于哪段画面？属于的话按那段画面挪，不按底下压着什么挪。
- 夹在 0 只对没有源时间的东西无害；有源时间的段要裁头，不能平移。
- 长期约束写在 [联动](../architecture/timeline-linkage.md)规矩 13、[声音怎么过一刀](../architecture/cut-sound.md)。
