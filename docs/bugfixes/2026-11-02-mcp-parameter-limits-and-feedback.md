# 2026-11-02 MCP 参数被静默截短，返回值与时间线不一致

## 症状

AI 请求较长图片、较大音量或四边裁切时，部分值被静默夹回限制，调用却返回成功，后续操作建立在错误的时长、
响度和取景假设上。图片刚导入、尺寸未就绪时，编辑失败也没有明确区分可重试与素材不可用。

## 根因

- 限制分散在静帧素材、原生模型、AI 写入及 MCP 说明。原代码的静帧长度确实有限，增益上限来自线性增益，
  不能直接照用户回忆的 dB 数字修改产品限制。
- 图片窗口 / 速度 / 四边裁切等输入先被夹紧；结果缺少 requested / applied。音量摘要只留一位小数，
  也没有按已有音量曲线的实际段首值读回。
- 缺尺寸既可能是静帧正在转换，也可能需要探测或文件已经不可用；只有一个“稍后再试”的解释。
- 真实 App 回归额外发现：单项工具的路由在校验之前打开撤销组。Foundation `UndoManager` 即使没有任何 action，
  begin/end 的空组也会使 canUndo 变真。时间线虽然没改，失败请求仍留下空撤销记录。

## 修复

- `AIEditLimits` 从生产类型读取限制；原生速度、手动裁切和 MCP 取景范围分别有共同常量。
  `AIClipSourceWindow` 同时供新增 / 编辑使用。图片 / 速度 / 手动取景非法值拒绝，返回合法范围和有效建议。
- `AIParameterReport` / `AIOverlayParameterReport` 从最终模型读实际值；原有音量、曲线、淡变、角度、透明度、
  关键帧及文字 / 形状限幅继续生效，但每个调整都有 requested / applied / reason。
  关键帧反馈直接读取实际轨，避免复用舍入后的展示摘要。
- `MediaProbeCache` 合并真实在途任务并记成功 / 失败状态，`AIClipReadiness` 返回 `media_loading` 或
  `media_unavailable`。尺寸缺失先复用原生探测；探到的 info 和其他参数一起通过后才采用。
- 单项片段、推子、关键帧、文字与形状共用已有 `AIBatchEditTools.commit`。全部校验后才开撤销组；
  批量保留同一套规则和带下标的结构化错误，没有增加第二套事务。
- `get_timeline.edit_limits` 与结果内的 limits 提供运行版本的真实限制；MCP 说明不再复制原生音量、速度、
  图片和手动裁切的数字。保留旧单项接口、旧摘要字段与旧普通错误的纯文字合同。

## 验证

- `scripts/check-mcp.sh` 新增 `ParameterLimitChecks`：每类正常 / 边界 / 越界、有效建议、精确生效值、
  曲线 / 关键帧与原子性，以及文字 / 形状原生限幅反馈。整套 MCP 当前 3,066 条通过。
- `scripts/check-parameter-limits.sh` 使用完整 App 对象、独立 bundle、临时工程及合成媒体，62 条断言通过：
  多参数错误不改时间线 / 撤销 / 预览，单项与批量同限制、一次撤销，真实探测、静帧转换后同参数重试，
  文件缺失 / 探测失败与加载中分开，失败的后续校验不提前采用元数据。
- 反向验证：临时撤掉图片上限拒绝、精确音量反馈、加载中状态及校验后撤销四处修复，实际 App 检查退出 1，
  62 条中 21 条变红，四类目标断言均命中；随后四份生产文件按 SHA-256 核对逐字恢复。
  补充两组：建议值不考虑当前出点、曲线仍按裁切前起点计算、推子舍入 → 3 条红；
  撤掉“段首增益达标但曲线其他点饱和”的提示 → 1 条红，均逐字恢复。
- `scripts/check-all.sh` 全仓聚合：80 项通过，0 失败。反向恢复后再次通过参数真实 App 62 条、旁白同步 84 条、
  MCP 3,066 条，以及推送前完整 `scripts/check-guards.sh`；最新生产源码已重新编译。

## 教训 / 防回归

“原生允许限幅”和“调用成功等于原值生效”不是同一件事；AI 必须拿得到最终值。范围说明应引用生产来源，
不能靠手写的 dB 小数维护第二套限制。校验只在副本上做，连探到的元数据也不能提前写进工程；撤销分组同样属于
提交的副作用，不能包住可能失败的校验。
长期合同与人工回归清单见 [MCP 编辑参数](../architecture/mcp-edit-parameters.md)。
