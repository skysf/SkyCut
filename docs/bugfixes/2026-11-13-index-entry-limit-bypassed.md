## 根因

1. **守卫按一种物理前缀认「一条」，Markdown 的一条是逻辑上的。** `index($0, "- [") == 1` 只看顶格 `- [` 开头的那一行；
   可 Markdown 里 `+`、`*`、`1.` 照样是列表，缩进的行、紧跟着的不缩进的行都是上一条的续行，表格行也能当索引写。摘要换一种合法写法就长回来，
   每一行都不归守卫管。它量的是「有没有一行太长」，不是「一条一共多长」。
2. **收成一句话时按「主要意思」概括，限定被当成细节删了。** 带「只有」的句子留下绝对的主干，括号里的例外换成省略号；实测数字被从它的条件
   （客户端、构建、缓存）里拿出来拼成一句；只在一个入口生效的修法被写成泛指。旧摘要里这些限定都在，收短时一起删了。
   D1 当时的验证是「每一行的链接集合都在、规矩都在正文里」—— 这只证明文档找得到，证明不了一句话没说反。
3. **必读表的左列被当成摘要一起收了**，可它是检索线索：左列是别人按类型名、参数名搜到这一行的入口。

## 教训 / 防回归

1. **守卫要按被守的格式自己的规矩认「一条」。** Markdown 的一条是逻辑上的（列表记号、缩进、续行、表格行），按一种物理前缀数只拦得住老老实实的写法。
   写完拿「换一种合法写法」去打它，改之前的守卫绿、改之后的红才算数；只打「把那一行写长」这一种，验证的是守卫已经会的东西。
2. **收短文档时，「只有 / 一律」的例外、实测数字的条件、修法的适用范围都是规矩的一部分，不是细节。** 清单在
   [文档索引怎么写](../architecture/doc-indexes.md)第三节：例外写全或只写话题、数字带着条件、修法写明入口、左列的检索词别删、拿不准就照抄正文。
3. **「链接都还在」只证明找得到，证明不了没说反。** 收短之后要对着正文逐条读那一句话。
4. **不设上限的地方要写明是有意的、为什么**（必读表、检查入口），不然下一个人以为漏了，或者以为那里可以塞摘要。
