# 2026-11-10 Sky Studio 接线守卫最后三节的检查从来不会红

## 症状

做声音 PR 6（`feat/voice-library-mcp`）的反向验证时：在 `SkyStudioVoiceLibraryTool.swift` 里多造一处 `consent: true`、在测试数据里写一个 MiniMax
voice_id 的样子，`checks/sky-studio-wiring.sh` 都打出了 `✗ …`，**退出码却是 0**，最后还打一行「✓ sky-studio-wiring」。CI 只看退出码，这两条守卫等于没有。

## 根因

脚本的写法是「每条检查失败只 `fail` 记一笔（`FAILED=1`），最后一道总闸 `if [ "${FAILED}" -ne 0 ]; then exit 1; fi`」。总闸原来在第 436 行，
**后来加的几节都接在它后面**：角色 A 那一节（服务器引用、报价选择进确认身份）、2026-11-07「0.18.62 真积分验收后的结果边界」那一节，
以及这次新加的第 11 节（声音库）。它们的 `fail` 只打字、不再有人看 `FAILED`，所以脚本照样走到最后的「✓」、退出 0。
加那几节的时候大概只跑了正常的情况（全绿），没有反向验证「弄坏一处会不会红」——正常情况下前后两种写法输出一样。

第一次反向验证里 R12（去掉授权那一问）倒是红了：不是守卫认出来的，是 `gate_line="$(grep … | head -1 | cut …)"` 在 grep 找不到时整条管道失败，
`set -euo pipefail` 让脚本**一声不吭地**在那一行退出 1 —— 碰巧红、不说为什么，也是同一类问题。

## 修复

- 总闸挪到最后（所有检查之后、最后那句「✓」之前）。挪完角色 A、0.18.62 那两节照样全过（它们只是没被执行到退出，规则本身没坏）。
- 总闸前加一条**守卫自己的检查**：读自己这个文件，最后一条 `fail "…"` 的行号要小于最后一道总闸的行号，不然就红并说出两个行号。
  以后再有人把新的一节接在总闸后面，这条当场红。
- 第 11 节两条「找第几行」的管道加 `|| true`，找不到时照常走到 `fail`、说出原因，不再被 `set -e` 半路掐断。
- 顺手审了 `checks/` 和 `scripts/check-*.sh` 里其余带同样总闸写法的脚本：没有第二个把检查接在总闸后面的。

## 验证

反向验证（2026-11-10，每处单独打上、跑 `checks/sky-studio-wiring.sh`、再恢复）：

| 临时弄坏 | 修之前 | 修之后 |
| --- | --- | --- |
| `SkyStudioVoiceLibraryTool.swift` 里多造一处 `consent: true` | 打出 ✗、退出 0 | 退出 1，说出是哪个文件 |
| 测试数据里写一个 `Voice904740431752642196abcd` | 打出 ✗、退出 0 | 退出 1，说出是哪个文件 |
| 去掉建声音前的授权那一问 | 退出 1、什么都不说（`set -e` 掐断） | 退出 1，说「consent: true 要在 voiceConsent 点过头之后才造」 |
| 在总闸后面接一条检查 | —— | 退出 1，说出总闸和最后一条检查的行号 |

正常情况下照样全绿（「✓ sky-studio-wiring」）。

## 教训 / 防回归

- 「记一笔、最后一道总闸」的守卫，**总闸必须在最后**；新加一节一律加在总闸前面。写进了
  [写代码的规范](../architecture/coding-standards.md)第五节审查清单和 [shell 陷阱](2026-08-06-build-version-and-shell-traps.md)陷阱 7。
- 守卫只跑过「全绿」不算验证过（AGENTS.md 全局规则第 2 条：没红过的守卫不能算验证）；这三节当时缺的正是反向验证。
- `set -euo pipefail` 下，给变量赋值的 `$(grep … | head | cut)` 找不到就会半路退出：要靠它算行号的，加 `|| true`，再用 `fail` 说清楚。
