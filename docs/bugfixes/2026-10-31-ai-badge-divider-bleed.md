# 2026-10-31 小窗口的分栏线穿过 AI 状态

## 症状

单排工作台中，窗口缩小时，检查器对应的竖线从标题栏顶部穿过「AI 正在剪辑」的金色徽章。用户在实际测试窗口截图指出。长工程名还可能将导出 / 设置 / 更多推入系统的溢出菜单。

## 根因

AI 徽章只用 `Color.yellow.opacity(0.22)` 作背景。它是一层半透明着色，后方原生分栏线仍会参与合成；窗口宽度或分栏位置改变后，徽章和竖线相交，线就透过背景显出来。

曾尝试只移除 `NSTrackingSeparatorToolbarItem`：原生工具项测试通过，真实窗口的线却仍然存在。这说明该测试没有覆盖实际的透底路径；已撤掉这份无效清理代码，没有留下观察器或私有视图遍历。

另一个宽度问题来自原生工具栏对工程菜单固有宽度的分配。只给菜单一个弹性 frame 没能保证压缩优先级，AI 状态出现后右侧常用按钮被藏进溢出菜单。

## 修复

- `AIActivityBadgeBackground` 先铺不透明的系统窗口底色，再叠浅金 / 中性灰。圆角以外保持透明；内部后景不再透过。
- `AIActivityBanner` 使用这份背景，运行与完成 / 停止状态都覆盖。没有用另一条竖线遮盖，也不改变内容分栏的拖动。
- `VideoEditWorkbenchToolbar` 依据编辑器实际宽度和 AI 状态给工程菜单分配宽度；窄时先截短工程名，保住常用入口。导出进度用紧凑的环形显示。
- 主窗口与工程窗口分别使用公开的原生紧凑工具栏样式。

## 验证

- `scripts/check-workbench-toolbar.sh` 用 ImageRenderer **真正渲染生产背景组件**。在红 / 蓝两种后景上分别渲染运行 / 完成状态、浅色 / 深色共四种组合；徽章中心的像素完全一致且 alpha=1，证明后景无法透过。
- 反向验证：暂时撤掉系统底色，渲染检查必须报 `underlying divider bleeds through`；恢复后转绿。
- `checks/workbench-settings-wiring.sh` 守住状态按钮接这份背景、工程名接宽度预算，避免只测组件、生产路径却未接。
- 实际 App 在 1180 宽与最小约 900 宽窗口中复测：分栏线仍在内容列边界，徽章内部不再透线；长工程名缩短，素材库 / 录屏 / 字幕 / 导出 / 设置 / 更多都在工具栏中，没有落入系统溢出菜单。设置入口和 AI 详情仍能打开。

## 教训 / 防回归

半透明着色不能隔离背景；在原生标题栏里画浮动状态时，必须明确哪些内容可以透过。只测工具栏项目的类型 / 数量，覆盖不到最终的图层合成。

长期约束和小窗口、AI 状态、设置入口的人工回归清单在 [顶部工作台与统一设置](../architecture/workbench-and-settings.md)。
