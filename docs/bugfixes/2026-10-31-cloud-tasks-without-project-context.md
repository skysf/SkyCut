# 2026-10-31 多工程窗口的生成任务没有工程归属

## 症状

AI 只在一个工程生成视频，两个工程窗口却都写「生成任务 2」，打开浮层也分不出每项属于哪个工程。
用户选定「轻盈卡片」：先汇总全部，再展开当前工程，其他工程折叠；任务前用视频 / 音频 / 图片图标区分，暂不放取消按钮。
后台工程保留打开入口，并要求 MCP 随时能查各工程、各任务的详细进展。

## 根因

`CloudTasksButton` 读取全 App 的活动清单，不接收所在窗口的工程；`SkyStudioMediaStatus` 只有名字、模型、报价、阶段，没有原工程身份或媒体类型。
旧浮层平铺两类任务，入口数量把失败 / 已完成也算进去。`get_status` 虽然列出工程与 AI 任务，却没有面板发起的 upscale 或保留的问题及其工程关系。

## 修复

- `CloudTaskOwner` 在登记任务之前固定工程代号、身份 token、短 id 和名字快照；生成、配音、AI / 面板 upscale 的入口都必须提供。
- `CloudTaskGrouping` 按工程代号分组，不能按焦点、名字或可复用的工程对象分。总量只算进行中，问题与完成项单独计数；未知报价明确保留。
- 轻盈卡片当前工程始终展开，其他工程按代号记住展开状态；行只订阅自己的任务，详情里保留异常关闭 / 成片比较。媒体类型为枚举，浮层没有取消入口。
- 打开按钮动作时重新按代号核对注册表，再复用 `OpenProjects.focus`。工程已关或原对象已换内容时不提供打开按钮；窗口登记可被小视图观察，后台标记不会滞留。
- `CloudTaskReport` 把同一份分组和阶段暴露给 `get_status.cloud_tasks`；开着的工程各有 `cloud_task_summary` / `cloud_task_ids`，详情保留实际 `job_id`、服务端任务号与原工程 token。
- 实窗视觉验收发现当前卡片的强调线被同一 overlay 的兄弟布局推到中间；边框与贴顶强调线改为各自叠放，装饰层不接鼠标，复测强调线贴顶且详情可点。

- `swift build --arch arm64` 完整 App 构建通过；`scripts/check-all.sh` **75 项通过，0 项失败**，其中 cloud-media **121** 项、MCP **2,664** 项。`scripts/check-guards.sh` 扫描守卫通过；单独重跑当前入口的 `checks/no-legacy-generation.sh` 也通过。
- 英 / 中 / 西文 **1,036** 条界面文案的本地化覆盖通过；单文件体积、文档索引及 `git diff --check` 通过。
- **反向验证**：临时把 `group(for:)` 改成总取第一个工程，4 条跨工程 / 换内容 / 未知报价 / 空工程断言变红；临时移除生产 `get_status.cloud_tasks` 返回行，接线守卫变红。均恢复修复后转绿，完整 App 再构建通过。
- 真 App + 真 MCP 小程序 + 回环假服务：`scripts/gui-smoke/sky-studio/project_tasks.py` 通过。两个可见工程与一个后台工程分别 2 / 2 / 1 项，视频 / 音频 / 图片齐全，全局 5 项排队、预计 225 积分；真实 `get_job` 任务号可查。失败工程关闭后仍留原身份与服务端任务号；新 MCP 会话无需接管工程也能读全局明细，重复查询没有新增提交或花费。
- 用户允许接管鼠标后实窗点击：当前卡片展开、其他卡片默认折叠、详情展开 / 收起、视频 / 音频 / 图片图标、后台「打开此工程」、已有窗口「切换到此工程」、已关工程无打开按钮均通过。后台按钮确实打开自己的窗口，总数仍为 5，本工程为 1；已有窗口为 2；另建的空工程为 0，且写明暂无生成任务。浮层没有取消按钮。
- 真窗口核对英 / 中 / 西文，长工程名截断、卡片与详情可用；当前卡片强调线修正后重新验收。测试均使用独立 `.skystudiosmoke` 身份和假服务，未访问生产钱包或改动正式版工程。900pt 窗口、超过五项的滚动与完成 upscale 比较的完整发版回归仍按架构清单执行，本次未将它们报告为已实测。

## 教训 / 防回归

共享的是任务清单，工程归属必须是任务创建时的不可变身份；「总量」与「本工程」要明确区分。
界面和 AI 的查询应读同一份任务数据，不能由 AI 根据当前窗口猜。

长期约束与人工回归见 [Sky Studio 的任务](../architecture/sky-studio-jobs.md)第九节和 [AI 接口](../architecture/ai-control-mcp.md)第四节第 46 条。
