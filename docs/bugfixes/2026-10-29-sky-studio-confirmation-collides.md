# 2026-10-29 两种视频的报价拿到同一个确认码

## 症状

6b 真实验收先问五种生成的报价。文生视频、图生视频都是 MiniMax H3、5 秒、480p、50 积分，
虽然 kind、提示词和首帧不同，却拿到了同一个确认码。第一单用过以后，第二单的码也变成「已用过」。
在使用之前把码带到另一个同摘要请求上，还可能放行原来没问过的生成。

## 根因

`SkyStudioJobGate` 把显示摘要和保留一位小数的积分拼成 action。摘要没写 kind、提示词、全部参数和输入文件，
所以不同的请求变成同一件事。upscale 也只绑显示摘要，没有绑原片 / 范围 / 将替换的段。

## 修复

新增 `SkyStudioApproval`：按稳定排序的 JSON 绑定请求的 kind、model、prompt、全部 params / inputs、精确报价和调用方的上下文；
随机的 idempotency_key 不参与（同一件事重问仍回同一个码）。本机输入绑定路径、卷 / inode、大小、修改时间，原地换文件也换码。

生成入口补首帧、输出文件夹和名字；upscale 补原片、源范围、被替换的段和工程。闸门的完整身份参数不可省略，摘要只管显示。
闸门可注入隔离的积分账本，自检实际走「发码 → 拒绝串码且不记账 → 原码仍可用 → 只记一次」。

## 验证

- `scripts/check-sky-studio.sh`：653 条通过，其中 16 条新增检查覆盖实际闸门和请求 / 文件身份。
- 反向验证：将闸门的 action 临时恢复成旧的「摘要 + 一位小数报价」，新增实际闸门回归红 4 条，退出码 1；随后恢复修复。
- 接线守卫钉住两个生产入口确实构造并传入完整身份，不能只把纯函数测绿却继续用旧摘要。
- `scripts/check-all.sh`：75 项通过、0 失败；`scripts/check-guards.sh`：全部扫描守卫绿。
- 原 6b 的五单已查到 done、完整解码并入轨；服务端对账 129.4 积分，没有重复任务或退款。修复本身不用再花积分验证。

## 教训 / 防回归

显示给人的摘要不是一件事的身份。确认码必须绑定实际要做的请求和输入；价格要用精确值，不能用显示时的取整。
长期合同见 [Sky Studio 的任务](../architecture/sky-studio-jobs.md)「积分的每日上限」。
