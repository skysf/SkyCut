# 2026-11-04 官方配方收费前拒绝，本机预留未释放

## 症状

接入官方生成的隔离检查发现：报价成功并预留本机每日额度后，若服务端配置或保留版本不可用，
`POST /jobs` 明确返回 `503 recipe_unavailable`，旧判断仍保留本机额度、把结算说成未知。
这是本机预算与状态报告错误，不是已观察到的服务端多扣款；发现与修复过程没有真实付费生成。

## 根因

`SkyStudioJobError.canRefund(beforeAccepted:)` 只认可既有收费前错误码，没有纳入新合同的
`recipe_unavailable`。HTTP 503 本身确实不能证明没收费，但这个精确错误码明确表示没有提交。

接入持久回执时还暴露出第二个边界：只记“准备提交”而不记已知拒绝，重启后便会把已知未提交
误报成丢答。反过来，只凭错误码也不够；若同时携带已受理 / 实收或提供方拒绝证据，不能覆盖它。

## 修复

- `SkyStudioJobAdmission` 统一明确未准入的错误码，加入 `recipe_unavailable`；退款仍先看结构化账单与受理状态。
  一般 503、网络丢答、未知应答不释放预留，也不重放收费 POST。
- 官方回执记录确定的本机未发送或收费前拒绝。恢复返回 `confirmed_not_submitted` / `charged=false`，
  幂等 key 仍保留；有原单只查原单，无证据的丢答仍报 unknown。
- 任务号、实收 / 退款证据不能被后来的模糊状态覆盖。回执写入失败单独报告，不能假称恢复证据已持久保存。

## 验证

- `scripts/check-sky-studio.sh`：1,360 项通过，包括真实请求构造、假 HTTP 的 `recipe_unavailable`、
  已受理例外、未知网络结果、回执拒绝与恢复身份。
- 隔离副本撤掉 `recipe_unavailable`：退款与持久拒绝相关 3 项失败；实际工作树恢复后的专项检查通过。
  单独撤掉回执未准入保护：69 项检查中的 5 项失败，恢复后 69 项通过。
- 生产接线守卫覆盖官方入口、精确请求、提交前回执、只 GET 的恢复及工程归属；撤掉入口分流后守卫变红。
  实际工作树的 `scripts/check-guards.sh` 全绿。
- 真后台 App / MCP 的报价后拒绝、重启恢复及本地总检查证据继续记入
  [实施报告](../reports/2026-11-04-official-film-client.md)，未执行的步骤不计为通过。

## 教训 / 防回归

不要把 HTTP 状态码当作计费证据，也不要忽略合同中明确的“尚未提交”。回执应保存已经知道的事实，
同时保留无法知道的边界。长期规则见 [官方原创短片](../architecture/official-film.md)「提交回执与恢复」。
