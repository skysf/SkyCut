# 2026-10-14 Kokoro 配旁白：speed 从 0.95 改到 0.85 几乎听不出慢

## 症状

2026-10-06 审美盲测的南极片，AI 嫌 zm_yunxi 的旁白太赶，把 `add_voiceover speed` 从 0.95 改成 0.85 重配了一遍，新文件只长了一点点，
听不出慢下来；换一句又像是慢了。AI 以为参数没生效。

## 根因

`speed` 原样交给 Kokoro 模型（`KokoroEngine.synthesize`）。模型的做法是把每个音预测出的时长除以 speed、**取整到一格**（600 个采样，
25 毫秒）、至少一格：中文一个字常常只有两三格，除以 0.85 再取整经常还是那几格；句子里段和段之间按标点停的那一截（`KokoroVoicePieces`：
逗号 0.2 秒、句号 0.35 秒）也不跟着变。于是读出来的长短和要的语速对不上，而且每句不一样。实测（2026-10-14，本机 M1 上的同一个模型）：

| 声音 · 句子 | 要 0.85，读出来比目标短 | 要 1.2，读出来比目标长 |
| --- | --- | --- |
| zm_yunxi「岸上，小企鹅挤在一起，抵御寒风。」 | 6.8% | 8.1% |
| zm_yunxi「在地球的最南端，冰统治着一切。」 | 5.9% | 7.2% |
| zf_xiaoxiao「冰面上没有路，每一步都要试探。」 | 7.3% | 11.6% |
| af_heart 一句英文 | 8.5% | 5.7% |

0.95 → 0.85 本该慢 11.8%，第一句只慢了 4.7%。

## 修复

- 新增 `KokoroSpeedCalibration`（纯值）：按**时长**对准。`KokoroVoiceSpeech.render` 不是 1 倍时先按 1 倍读一遍，目标 = 1 倍的时长 ÷ speed；
  读出来差 3% 以上就再调给模型的 speed 再读：都在目标一边时用最后两次拟合「时长 = 停顿 + 说话 ÷ speed」解出来，两边都有了就在离目标最近的
  两次之间插值（时长是一格一格跳的，外推会冲过头）；最多再读四次，留最接近的那一次。1 倍不多读。
- 原来读一句的那段改名 `renderOnce`，其余不变（切段、垫句、拼接、词的时刻都照旧，字幕的词时间跟着最后用的那一次）。
- 长期约束写进 [AI 接口（MCP）](../architecture/ai-control-mcp.md) 配旁白那一节「语速不是线性的」。

## 验证

- 真模型（本机，CI 上没有模型）：上表四句，校准后要 0.85 / 0.95 / 1.2 都在 3% 以内（最大 2.3%），每句最多读五遍（1 倍一遍 + 四次），多数三四遍。
- `scripts/check-mcp.sh` 的 `KokoroSpeedChecks`：照模型的样子造一句（固定停顿 + 40 个音、每个音按 speed 缩放后取整到整格），要 0.85 / 0.9 / 1.15 / 1.3
  时直接给模型要的 speed 对不上（症状），校准几次之内对到 3% 以内；一长一短之后下一次夹在中间；推不出范围。扫描钉着 `render` 先按 1 倍读、按
  `KokoroSpeedCalibration.next` 调。
- 反向验证：见 PR 描述（不合并的草稿 PR，CI 上跑）。

## 教训 / 防回归

- **模型的参数名叫 speed 不等于它线性地管语速**：取整、固定的停顿都会吃掉一截。要让 AI 的参数「要多少给多少」，就量结果、按结果调，
  别信参数本身。
