# 2026-10-30 添加 Sky Studio Key 后，旧 AI 会话仍看不到生成工具

## 症状

正式版 0.18.53 中，用户已开通 Pro、有积分，Codex 能调用 Sky Studio 配旁白，却反复说 MCP 没有图片 / 视频生成接口。
原会话北京时间 09:42 开始时 `get_status` 返回 `source: no_key`；09:49 已返回 Pro、`ai_tools: true`，
但 10:16 再列会话工具仍只有 46 项，缺 `generate_media`、`upscale_clip`。随后新会话能看到完整的 48 项。

## 根因

两个生成工具按 Key 是否存在过滤，总说明里的 Paid 目录也按 Key 拼接。Key 中途加入后，App 的状态已更新，
客户端提供给模型的工具仍是会话开始时的那份。现有实现虽发 `notifications/tools/list_changed`，
却不能保证客户端在运行中的会话里重新加载工具；通知是否送达及客户端在哪一步未采纳，当前日志不能进一步归责。

原有检查只证明「通知发出、客户端主动再请求会拿到新清单」，没有覆盖客户端不再请求清单的实际情况。
`add_voiceover` 始终列出、调用时才选云端声音，所以同一会话里配音成功、生成素材却不可见。

## 修复

- 工具清单及总说明始终列出生成和 upscale；提供方只描述服务归属，不再作为清单过滤条件。
- App 交给旧 helper 的清单不携带隐藏条件；新 helper 读取旧 App 的清单也不按提供方删工具。
- Key、套餐、每日积分上限和实际报价继续由 App 在调用时核对；可发现工具不等于有权限消费。
- 取消 Key 变化引起的清单通知；App 升级后的清单变更通知照旧保留。
- 工具说明明确需要 Sky Studio Key 和积分，删掉「因为已配置 Key 才列出」这一过期描述。

## 验证

- `scripts/check-mcp.sh`：**2,660 条通过**；包括两代协议、真 helper 的首次完整清单、Key 中途添加 / 删除，以及新旧 App / helper 的过滤兼容。
- 反向验证：临时把 `MCPToolName.listed` 恢复为按提供方过滤，真实 helper 回归 **7 条失败**（首次发现、缓存清单、Key 变化后的稳定性）；自动恢复修复。
- 新检查在完整旧实现上也实际运行过，**12 条失败**；首次编译被沙箱拦住、一次编译中修改输入导致的无效运行均未计作回归证据。
- `scripts/check-all.sh`：75 项全部通过；`scripts/check-guards.sh`：全部扫描守卫通过。
- 没有生成真实媒体、读取生产 Key 或新增付费请求。

## 教训 / 防回归

需要用户在会话中开通的能力，必须从第一次工具发现开始就有名字。客户端能缓存清单，动态授权必须在执行处核对。
长期合同见 [AI 接口（MCP）](../architecture/ai-control-mcp.md)第四节第 39 条和
[Sky Studio 的任务](../architecture/sky-studio-jobs.md)「清单」。
