# 2026-10-29 MCP 冒烟丢掉断线和协议错误，后台包装又把失败报成成功

## 症状

6b 的真实积分测试在第一个 `music duration=30` 拒绝检查处只留下 `_queue.Empty`，
后台通知却说 exit 0。五种正式生成的循环根本没执行，不能把这条通知当作测试通过。

## 根因

`scripts/gui-smoke/fal/mcpclient.py` 的读线程遇到 EOF 直接结束，遇到坏 JSON 直接跳过，
等回答的队列都没人唤醒；到点只冒出没有调用名的 `_queue.Empty`。另一个确定的缺陷是
`call()` 不看 JSON-RPC 的 `error`，把它读成空的成功结果。超时也不清理等待表。

原临时后台命令以 `python3 …; echo "exit=$?"` 结尾，外层的退出码来自 echo，所以脚本
本身 exit 1，后台通知仍是 exit 0。原调用没有保留收发证据，**本案例不把这些诊断缺陷
冒充原来 120 秒超时的具体原因**；也不能由本地没有任务推断服务器从未扣费。

## 修复

- MCP 冒烟客户端遇到 EOF / 坏协议唤醒所有等待者，JSON-RPC 错误明确失败；超时写明
  工具名、请求号和结果未知，清理等待表，不自动重送；关闭时回收小程序和管道。
- `scripts/gui-smoke/run-logged.sh` 作为后续冒烟的日志入口，原样传出被测命令的退出码。
- `checks/MCP/SmokeClientChecks.py` 真起假的小程序测以上行为，并实际运行日志包装验证
  exit 7 原样传出；接入 `scripts/check-all.sh`，不碰 App、网络或付费接口。

## 验证

- 反向验证：只加回归、保留旧客户端时，6 条里 5 条红（EOF、坏 JSON、超时只有
  `_queue.Empty`，JSON-RPC 错误未失败，日志包装不存在），健康回答那条绿。
- 恢复修复后，同一命令 `python3 checks/MCP/SmokeClientChecks.py`：6 条全部通过。
- `scripts/check-all.sh`：75 项通过、0 失败；`scripts/check-guards.sh`：全部扫描守卫绿。
- 先核查运行中 Beta 0.18.51 无本地任务；Sky Studio 读库确认历史停点之后无新任务 / 扣费、冻结为 0。
  同一个 `music duration=30` 在 2026-10-28 17:00:50Z 开始，约 4.96 秒后正常返回服务器的参数拒绝。
  原来的超时未复现，不能倒推它当时卡在哪一层。
- 用户确认累计 500 积分预算后，五类各一单全部 done、完整解码并入临时工程；服务端对账新增恰好 129.4 积分，
  累计 345.4、无退款、无冻结。验收脚本一次时间字段重名导致的 exit 1 被日志包装正确保留；只续验文件和入轨，未重交生成。
  这些实际生成结果与本地假小程序的回归分别记证，不能相互冒充。

## 教训 / 防回归

测试客户端本身就是证据链的一部分。结果未知不能当作没做，更不能自动重送付费调用；
后台通知必须传出被测进程的退出码。长期约束见
[AI 接口（MCP）](../architecture/ai-control-mcp.md)「冒烟客户端的失败证据」。
