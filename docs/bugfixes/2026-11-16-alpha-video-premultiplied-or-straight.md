# 2026-11-16 带透明的视频：预览当预乘、成片当直通，同一个文件两边不可能都对

## 症状

网页动效小试验（2026-11-16）把 AI 写的片名动效渲成带透明的视频（ProRes 4444、HEVC 带透明）放进上层轨：透明的地方透得过去，
可半透明的地方（光、羽化、闪白）预览和成片对不上 ——

- 存**预乘**的文件：预览对，成片半透明处暗 18–35 级（满分 255），光发灰、闪白变脏；
- 存**直通**的文件：成片对，预览半透明处亮 74 级，冰缝的光成了一条白带。

同一个文件不可能两边都对。连带两处没试过的：带关键帧的上层轨段（fill + matte 预渲染）用纯白的 matte，带透明的视频一加关键帧
透明的地方就是黑方块；HEVC 带透明是长 GOP，开着「优化媒体」会被转成 H.264 的代理 —— 代理没有 alpha，预览里又是黑块。
主轨上的直通文件也一样：成片丢 alpha 之前没预乘，透明处露出存着的颜色。

## 根因

1. **两条管线各按一种约定读，都不看文件里的标记**：预览的默认合成器把源一律当预乘的用；导出图只有透明静帧（`isAlphaStill`）
   才先标明预乘再反预乘，别的带透明的段一律按 ffmpeg overlay 的直通混合。AVFoundation 写带透明的 ProRes 4444 / HEVC 时其实在
   样本描述里放了 `almo` 盒子（预乘 `0x0102`、直通 `0x0100`），两边都没读。
2. **CoreMedia 替没有标记的文件补了一个「直通」**：ffmpeg 写的 ProRes（透明静帧就是）、`concat -c copy` 接过的文件没有 `almo`，
   CoreMedia 的 `AlphaChannelMode` 照样报 StraightAlpha —— 只看这个值，透明静帧会被当成直通（实测；所以认标记要先看盒子在不在）。
3. **预览那边没有「按标记预乘」的开关**：解码器给的就是文件里存的值（直通的不替你预乘），图层指令只有整层的不透明度 / 变换 /
   裁切，VideoToolbox 的像素转换没有 alpha 模式这一项；能逐层处理的只有自写合成器，产品决策不许。
4. **matte 和优化媒体都只为不透明的视频设计**：纯白 matte 只管摆放框；代理是 H.264。

试验报告说「ffmpeg 自己读不了苹果 HEVC 带透明的透明度」—— 本仓库带的 ffmpeg 8.1（和 Homebrew 的 9.0.2）都把它解成
`yuva420p`、带 alpha 平面，导出图就是这样拿到透明度的，问题只在当成了直通。

## 修复

长期约束写在 [定格 / 静帧管线](../architecture/freeze-frame.md) 第 4a3 节「带透明的段」，这里只列改了什么：

- **认标记只有一处**：`SourceAlpha`（`MediaProbe.swift`）—— 有 alpha 通道、有 `almo` 盒子时按 CoreMedia 的值，没有盒子按预乘；
  探测时写进 `MediaInfo.alpha`（随工程存）。老工程没记的，预览合成和导出图在入口用同一个函数补认（`CompositionSource.resolvingAlpha`）。
- **静帧和视频一个判断**：`EditClip.sourceAlpha`（透明静帧按名字认作预乘）。垫黑底（`needsOpaqueBase`）、「盖满画布且不透明」、
  导出怎么叠、预渲染的 matte、要不要换代理都只问它。
- **导出**：`ExportTransformChain.premultipliedEntry` —— 预乘的标明预乘，直通的标明直通再 `premultiply`；裁切缩放在预乘的画面上做，
  缩放完 `unpremultiply` 交给 overlay。主轨的轻量路径丢 alpha 之前也走这一步（= 压在黑底上）。
- **预览**：直通的源在 AVFoundation 那一边（预览、AI 的 look、带关键帧段的预渲染）换成一份预乘的 ProRes 4444 副本
  （`AlphaSourceCopies`：逐帧照抄时间戳和旋转矩阵、颜色标记照抄解码器给第一帧标的，缓存、同一份只转一次、在 `MediaReadQueue.alpha`
  上跑）；成片读原片。换哪条轨在 `CompositionSource.track`（从 builder 拆出来，带走了 `proxyTracks`）。
- **关键帧**：带透明的视频的 matte 是 `AlphaSourceCopies` 逐帧抽的灰度遮罩（同透明静帧那份），裁切、翻转、时间、关键帧照抄。
- **优化媒体**：`needsProxy` 对带透明的源说不；`CompositionSource` 对带透明的段不给块（老工程转过的块也不换进来）。
- 腾行数：`ClipPlacement` 原样搬进 `VideoEditClipPlacement.swift`（`VideoEditModels.swift` 935 → 862），builder 846 → 833，基线改小。

## 验证

- `scripts/check-video-fade.sh` 新的一组（`checks/VideoFade/AlphaVideo.swift`）：AVFoundation 现做 320×180 的四条带（全透明 /
  50% 的绿 / 不透明的蓝 / 25% 的白），存成 ProRes 4444（预乘、直通、存预乘却不写标记）和 HEVC 带透明（预乘、直通），压在红色主轨上，
  预览（生产 builder）和成片（生产 `plan()` + ffmpeg）各取四条带的中心和参考比（参考 = 这条管线自己的解码器解出来的预乘色 × 不透明度
  + 同一条管线只放底片时量到的底色 ×（1 − alpha × 不透明度）；全透明那条带就得等于底色）。组合：静态、不透明度 0.6、渐入走到一半、奇数边裁切 + 缩到一半、
  关键帧（fill + matte）、入场动画（预渲染）、单独在 V1、V1 + 不透明度、没记标记的老段、2560×1440 的画布、硬件编码、

  预乘副本标明预乘 / 颜色乘过 alpha / 和原片一样长、遮罩灰度 = alpha、`needsProxy` 对带透明的源说不（同样的长 GOP 不透明源照转）。
  这台机器做不出 HEVC 带透明、用不了 `h264_videotoolbox` 时，那几条打 `SKIP …` 明说没跑，不算过。

## 教训 / 防回归

- **预乘还是直通是文件的一部分，要读，不要猜**：两个消费者各按自己的习惯读，一个文件永远只有一边对。读之前先弄清「没写」长什么样 ——
  CoreMedia 会替没写的补一个值，只看那个值就把「没写」当成了「直通」。
- **平台没有开关的地方，换一份数据，不要换合成器**：默认合成器只认预乘，那就给它预乘的数据；成片照读原片。
- **辅助素材要带上主素材的性质**（2026-10-03 那条再撞一次）：matte、代理、预渲染的每一路都要问一句「源自己有没有 alpha」。
- **自检的素材自己标明色彩**：不写标记时解码器按尺寸猜（小图猜 601、高清猜 709），两种猜法混在一张画面里能偏七八级，会盖住真正要量的差。
- **参考值别从被测的那一帧里取**：「透明处露出底色」本身就是要验的，拿同一帧里透明那条带当底色，它错了参考跟着错 —— 底色要在同一条
  管线里单独量（只放底片）。
