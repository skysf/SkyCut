# AI 多开：一个 AI 会话同时剪几个工程

> 2026-10-17 用户拍板，**尚未实施**。这里记要什么、查清的事实、每一条板和理由、分刀；实施后已生效的规则写进
> `docs/architecture/`（主要是 [AI 接口（MCP）](../architecture/ai-control-mcp.md)），真实进度看 PR 和 `docs/reports/`，
> 不要回头把这里当现状。

## 用户要的

2026-10-17 用户问「软件能不能通过 AI 多开，比如同时剪 5 个视频」。讨论下来，真实的用法是**一个** AI 会话（Claude Code
开子代理并行）被告知「这 5 个文件夹各剪一条」或「同一个文件夹出 5 个版本」，可以选后台（不开窗口）或看得见；后台时要用户
点头的事在 AI 的聊天窗口里问。

收益在「几个 AI 同时想、同时下手」。App 自己的吞吐省不了：转写、分镜、导出、配音都是一次一个（见事实第 8 条），所以这些活
要排队，并且告诉 AI 排在第几、让它先把慢的活排上。

## 先查清的事实（2026-10-17，main 73aef4e）

1. **工程是单例**：`VideoEditProject.shared`（`VideoEditProject.swift:14`，`private init`），全仓 30 处、9 个文件直接读它。
   AI 的工具都已经收一个 `project` 参数，路由（`AIToolRouter.execute`）里只有一处 `VideoEditProject.shared` —— 换成按 id 找
   工程，工具本身几乎不用动。
2. **只有一个窗口场景**：`Window("SrtFlow", id: WindowID.main)`，剪辑页 `VideoEditView` 在 init 里拿单例。它的按键监听
   （空格、V、⌫、⌘A……）不看事件是哪个窗口的，录屏的设置页 / 残缺框 / 恢复框也挂在它身上 —— 开两个剪辑页的话，按一次空格
   两个都播，残缺框两个窗口各弹一个。
3. **撤销管理器借窗口的**：剪辑页出现时 `project.undoManager = 窗口的`，没有时 `effectiveUndoManager` 退到
   `NSApp.keyWindow?.undoManager`。几个窗口时这个退路会把改动登记进**别的工程的窗口**。主窗口被关时这份历史跟着窗口没了
   （AI 现在靠 `AIEditorPresenter` 把窗口开回来才能继续登记）。
4. **会话的绑定（10-14）是「一个会话一个工程」**：小程序记一个工程（`MCPSessionProject`），App 只核对「开着的是不是它」
   （`AIProjectBinding`），**不加工具参数**（[案例](../bugfixes/2026-10-14-ai-edits-land-in-another-sessions-project.md)）。
   一个会话开几个工程时这个前提不成立：Claude Code 的子代理共用同一个小程序，子代理 A 刚 `new_project`，子代理 B 不带参数
   的调用就落进了 A 的工程。
5. **一轮 / 停止 / 撤销这一轮 / 看得见还是后台**全 App 一份（`AISession.shared`）：停止取消所有任务（`AIJobs.cancelAll`），
   横幅只有主窗口那一条。
6. **路由的排队全 App 一条**（`AIToolRouter.tail`）：五个子代理的调用一个接一个做，谁在 await（探素材、Vision 认画面、
   合成配音）别人全等着。
7. **工作区的「当前文件夹」全 App 一份**（`AIWorkspace.current`）：相对路径按它解析，新工程 / 成片默认放
   `<它>/SrtFlow/…`（`DefaultFolder.start`：点名的文件夹 → 工程的家 → 下载）。几个子代理各 `open_folder` 一个文件夹时，
   谁最后开的算谁的。
8. **一次一个的活**：导出（`VideoEditExporter.shared` 只有一个，AI 第二个导出直接报「An export is already running」）、
   转写 / 生成字幕（`TranscriptionTask` 一个串行槽）、分镜（`MediaReadQueue.shots` 宽 1）、配音（`voice` 宽 1）、
   优化媒体（`proxy` 宽 1）；看 / 识别画面（`analysis`）宽 2。
9. **清单的字数**：全清单约 84,900 / 90,000 字符（47 个工具，含 fal 的两个）；总说明 1,927 字，配了 fal 时 2,047 / 2,048。

## 拍的板（用户，2026-10-17）

| --- | --- | --- |
| 1 | 工具加可选参数 `project`；`open_project` / `new_project` 回短 id（`p1`…）；**不给 = 这个会话最后打开的那个**；子代理必须每次带 | 子代理共用一个小程序，「当前工程」会串台（事实第 4 条）。10-14「不加参数」的前提只对「一个会话一个工程」成立。不带参数的老用法照旧能用 |

## 我定的细节（理由写在每条后面）

### A. 工程的身份、放在哪

1. **短 id 全 App 按打开顺序发**：`p1`、`p2`……，这一次运行里不重用（关掉的号不再发给别人，免得 AI 拿旧号改到新工程上）。
   App 重启后从 `p1` 重来：小程序记着的旧工程带着旧运行的代号（10-14 的 `ProjectStamp.token`），App 认得出「重启过」、照旧说清楚。
2. **同一个文件只开一份**：两份同时自动存盘会互相盖掉。`open_project` 开一个已经开着的文件 = 拿到它（自己的直接回它的 id，
   别人的按 B.3）。
3. **三种摆法**：主窗口（剪辑页里那一个，用户的）、自己的窗口、后台（没有窗口）。
4. **AI 新开 / 新建的工程放哪**：后台模式 → 后台。看得见 → 主窗口里是「空的」（没存过、没内容、没改动、没有会话在剪）就装进
   主窗口（一个会话剪一条时和以前一模一样），否则开一个自己的窗口：层叠排开，摆到最前面一次但**不激活 App**（键盘留在用户那边）。
5. **用户在主窗口开 / 新建别的工程时，AI 在剪的那个不关**：挪进它自己的窗口接着剪（以前是 AI 下一步被拒「用户换了工程」）。
6. **用户关掉一个工程的窗口 = 它转到后台**（AI 还在剪就接着剪）；在列表里能关掉它（I.2）。

### B. 一个会话一组工程

1. **小程序记这个会话的一组**（id → `ProjectStamp`）和「最后打开的那个」：带 `project` 的按 id 找，不带的 = 最后打开的那个（板 1）。
   `close_project` 做成了从组里拿掉；最后打开的那个被关了，就退到组里剩下的最近打开的那个。
2. **App 记每个工程归哪个会话**：打开 / 新建它的那个；主窗口里用户自己的工程，第一个碰它的会话收下它（同 10-14）。
   带着别的会话的 id 来 → 一样都不做，说清楚是谁的（哪个客户端）、该怎么办（先问用户）。
3. **别的会话开着的文件，`open_project` 它时**：那个会话 **5 分钟内**调用过 → 不给，说清楚；安静 5 分钟以上 → 算它放手了，
   转给这个会话（原来那个会话再来时被拒、说清楚是被谁接手的）。理由：会话结束时 App 不知道（一次调用一条连接，小程序退出没有
   信号），昨天那个会话没关的工程不能一直锁着；5 分钟足够区分「在剪」和「早就走了」，判错的代价也只是对面下一步被拒、去问用户。
4. **结果里带 `project`（短 id）**：AI 一眼看出这一步落在了哪个工程上。子代理忘了带参数时（板 1 定的默认是最后打开的那个），
   它看得出不对。
5. **不碰工程的任务也记会话**：`cancel_job` 只取消自己会话的任务。

### C. 路由按工程排队

碰工程的调用**按工程排**（同一个工程的调用仍按到达顺序一个接一个，「接在 V1 最后」不乱），不碰工程的按会话排，**不同工程之间不
互相等**。一个工程里的 await 只堵它自己（事实第 6 条）。排到之后、动手之前照旧核对（10-14 的顺序不变）。

### D. 工作区的文件夹按工程记

- 每个工程记一个**工作区文件夹** = 打开 / 新建它时这个会话点名的那个文件夹（没有就是工程的家）。碰工程的调用按它解析相对路径、
  决定成片放哪（`DefaultFolder.start` 的「点名的文件夹」换成这一个）。一个会话剪一条时和以前一样。
- 不碰工程的调用（`open_folder` 之后、`new_project` 之前）按**这个会话**最后点名的文件夹；点名过、能读的文件夹（`AIReadGrants`
  的范围）仍是全 App 一份。
- 子代理并行时「谁最后 `open_folder` 谁说了算」在建工程那一刻仍会撞：说明里写明**先把几个工程都开好 / 建好，再把 id 分给子代理**
  （主代理本来就知道是哪 5 个文件夹）。

### E. 一轮、停止、撤销这一轮按工程

- `AISession` 拆开：**每个工程一份「这一轮」**（快照、改了几处、停了没有、哪个客户端在剪）；按会话记的是默认看法（F）；
  全 App 一份的只剩要用户动手的提示（系统弹框在主窗口前面弹，提示也写在主窗口）。
- 横幅在每个工程的窗口里，只管它自己的那一轮。**停止 = 取消这个工程的任务**（导出、生成字幕、翻译、upscale、生成），之后这个
  工程的调用回「用户按了停止」，直到它安静 10 秒（现行规矩）；别的工程照剪。
- 任务（`AIJobs`）记着工程和会话；不碰工程的任务（压缩 / 烧录 / 转字幕格式 / 转写文件 / 扫文件的镜头）记成发起时这个会话最后打开的
  工程 —— 停那个工程时一起停。

### F. `set_view`

- 带 `project`：只改那一个。看得见 = 挂上窗口、摆一次；后台 = 摘掉窗口转后台；主窗口里的那个不挪，只是不再跟着选中 / 挪播放头
  （现在的后台模式）。
- 不带：改这个会话的默认（之后新开的照它，板里定的），**并且它已经开着的工程也都照它**。只改默认有个坑：老用法是先 `open_project`、
  问过用户再 `set_view background`，只管「之后新开的」的话，用户说了后台，开着的那个窗口还摆在前面。

### G. 撤销管理器每个工程一个

不再借窗口的、不再退到 keyWindow 的（事实第 3 条）。后台工程也有自己的，挂上 / 摘下窗口不丢历史，AI 的 `undo` 和窗口里的 ⌘Z 撤的是
同一份。窗口里的 ⌘Z 怎么接到工程的那一个**先做探针**（①b 第一步）：工程窗口由 AppKit 自己建、window delegate 的
`windowWillReturnUndoManager` 交出工程的那个（文档里写明的接口）；对照 SwiftUI `WindowGroup` + 响应链上的一层视图。
同时看工具栏（`NSHostingView.sceneBridgingOptions`）、sheet、应用内语言都正常，挑全过的那条。
**主窗口是 SwiftUI 的场景、改不了它的 delegate**：主窗口里的工程照旧用主窗口的撤销管理器（现状），从主窗口挪出去的工程（A.5）
带不走 ⌘Z 的历史 —— 「撤销这一轮」按快照换回，照样能用。探针能接上主窗口的话这条就没有了。

### H. 后台工程（headless）

- 不挂播放条目、不建预览合成、不开音频引擎、不转优化媒体；没有时间线，缩略图、波形条也不会去读。`PlayerClock` 留着当播放头的数
  （`AVPlayer` 不挂条目不解码），挂上窗口时重建一次预览。
- AI 的「看」「听」、导出、字幕本来就不靠播放器（各自建合成、读波形那一份）—— 后台照常。
- 系统弹框：翻译下载语言要主窗口里那个常驻的翻译宿主（`TranslationHostView`）：主窗口关着就开回来、摆到后面，SrtFlow 激活让用户点；
  `waiting_for_user` 照旧写进结果，列表那一行也写。

### I. 主窗口的「AI 在剪的工程」

1. **侧边栏多一栏**，只在有 AI 开着的工程时出现：每行 名字（+ `p3`）、在做什么（在剪 / 导出 42% / 排队导出第 2 个 / 等你点下载 /
   空闲 / 已停止）、Stop、打开窗口。
2. **我加了「关掉」**（已存盘、没在做事时才能点）：后台工程没有窗口，AI 忘了 `close_project` 的话，用户只能退出 App 才能清掉。
3. 主窗口被关了：点 Dock 图标开回来（现成的行为）。

### J. 确认码（板 9）

`generate_media` / `upscale_clip` 超了每日额度、或价格不明时**当场回 `needs_confirmation` + `confirm_token`**（删文件那一套
`AIConfirmations`，令牌绑着这一次的模型和估价）；AI 在聊天里问，用户同意后带着令牌再调，才起任务、才记账。提示条上的问题
（`AISession.ask`）撤掉。会回 `needs_confirmation` 的地方从两处变成三处，守卫跟着改。配旁白（同步工具）照旧不问、额度不够退档。

### K. 排队与位置（板 6）

- **导出排队**：一次一个、先来先做，面板上手动导出也排进同一条；AI 第二个导出不再报错。
- 生成字幕 / 转写 / 翻译：一个串行槽改成排队。分镜：`shots` 队列本来就排着，补上位置的账。
- `get_job` 排队时报 `status: queued` + `queue_position`（1 = 下一个）。
- **配旁白先不排**：它是同步工具，`voice` 宽 1，几个工程同时配会互相等、调用可能超过客户端的一分钟（已知不足，真撞上再改成任务）。

### L. 版本名（板 5）

- `new_project` 收 `version`：文件名 `<名字> - <版本>.srtflowproj`；`export_video` 默认名就是工程名（已经带着版本），也收 `version`。
- 「要 AI 给」落地成：**这个会话在同一个文件夹里已经有一个开着的工程、又不给 `version`** → 报错，叫 AI 给一个。

### M. 封顶

主窗口里那个也算，一共 8 个。到顶时 `open_project` / `new_project` 报错，列出这个会话已存盘、没在做事、可以关的那几个。

（`scripts/gui-smoke/mcp-client/client.py` 自己起小程序，不受会话里旧工具定义的影响），写 `docs/reports/`。

## 清单预算

- 动手前约 84,900 / 90,000。② 把上限抬到 100,000（板 10）。`project` 参数的说明全清单只写一句、在一处加到每个碰工程的工具上：
  约 120 字 × 40 个 ≈ 4,800；`close_project` 约 700；`open_project` / `new_project` 的说明多一两句 ≈ 300；④ 的 `version` ≈ 300。
  合计约 91,000，给以后留约 9,000。

  先把别的行收短腾地方；「几个工程一起剪时每次带 project」写在 `open_project` / `new_project` 的说明里（AI 拿 id 一定会读到），
  不进总说明（[第一节第 6 条](../architecture/ai-control-mcp.md)：总说明只放要 AI 主动做的事）。

## 风险与已知不足

- **撤销怎么接**（G）没探过；探不通时主窗口里的工程照旧用主窗口的撤销管理器，挪出主窗口丢 ⌘Z 历史。
- **性能 ratchet**：根视图改成读注册表里的工程，冒烟场景里注册表不变，计数应该不动；新加的列表、每个窗口的横幅都要接计数、不许涨。
- 五个看得见的工程 = 五个播放器 + 五个音频引擎：封顶 8 个；看得见的工程多时建议用后台。
- Claude 桌面版的几个对话共用一个小程序，算一个会话（10-14 的已知不足照旧）。
- 子代理忘了带 `project` 会落在这个会话最后打开的那个上（板 1 定的默认）：靠结果里的 `project` 和说明里那句兜底。
- 配旁白不排队（K）。
