# 官方原创短片：公开镜头合同与私有配方边界

> 2026-11-04 起。生成与计费仍走 [Sky Studio 任务](sky-studio-jobs.md)，工程归属仍走
> [开着的工程](open-projects.md)。本文只记录客户端公开合同，不收录配方、选择条件或学习来源。

## 一、职责

- 当前 AI 会话负责把用户意图整理为公开故事、分镜、世界状态和声音计划。没有额外的云端分类模型。
- 官方入口只接受 `original_film` / `science_fiction` / `none`，种类限图片、文生视频、图生视频。
  不支持的题材或场景明确拒绝，不能替用户改成另一种场景，也不能把普通生成称为官方配方生成。
- 客户端只持有公开声明和不透明凭据。私有配方选择、投影、版本保留、账户和价格绑定由服务端负责。
  不把私有 profile、研究全文、原片帧、原声音或来源映射写进工程、日志、安装包或工具结果。
- 用户已有的剪辑风格和 `recipes` / `save_recipe` 保持独立，不能用它们编辑官方配方。

## 二、请求与报价

`SkyStudioFilm` 是单镜头的公开合同：当前镜头的 context、序号、修订、entry / exit / actions，
左右邻镜的完整 render、状态和切镜声明，以及共同的声音计划。字段、枚举、字符串与数组边界严格校验；
缺 context 不填默认值。客户端不内置服务端支持场景的私有选择表。

普通请求不带 `film`，保持原来的 quote 行为。官方 `POST /quote` 必须带实际的 `inputs`、
原顺序的 image references 和完整 `film`；数量占位不能代替实际资产。首帧、尾帧与多参考的角色不能互换。
官方无素材模式只允许原创图片引用；文件归属由服务端核实，归属不等于原创来源证明。

报价中的 `official_recipe` 包含不透明 `recipe_pin`、到期时间及左右 `seam_review` 指纹。
提交使用同一请求、同一实际引用、精确价格、pin 和当前两侧审查。中间镜头从 revision 1 起就必须两侧齐全。
到期、修改当前或邻镜、参数、引用、状态、声音、cut 后必须重报价和重审，不能自动填旧确认。
pin 只用来传输，不解密、不当作可编辑的配方；服务端保留版本不可用时应在收费前失败。

## 三、世界状态与声音合同

- 连续切镜的边界状态必须相同，环境底床使用同一 `bed_id`。换机位不能解释换手、物体瞬移或重演动作。
- `completed_actions` 是累计历史。当前 `actions` 只能增加尚未完成的动作，exit 必须正好等于 entry 加新增动作。
- 有意跳时间、换地点或蒙太奇必须写明理由；`reset_fields` 只能且必须列出真实改变的字段。
  完成历史不能删除，跨缝新增动作必须列在 `offscreen_actions`。
- `music`、`environment`、`foley` 是公开的协调计划，不能据此声称已生成或听验。实际音乐、音效仍走普通生成或现有音频库。
- 实际验收应基于使用的源区间、最终时间线和成片切点；提交参考图、声明状态和报价审查均不能证明输出连续性。
  声点按最终可见动作对齐，画面改变后重新检查；数值测量与真实听辨分别记录。

## 四、验证与状态口径

纯值与假 HTTP 回归接入 `scripts/check-sky-studio.sh` 的 `FilmChecks` / `OfficialQuoteChecks`：
严格字段、显式 context、动作累计、双侧邻镜、精确 cut、原创图片 URL 与首尾角色、报价和提交同一输入、
缺官方回答不能退到普通生成、pin 有效期 / 当前双侧指纹，以及 film / 引用 / pin / 审查变化使审批身份失效。
提示词长度与服务端一致：先去首尾空白，再按 Unicode scalar 计数；状态短文字按 UTF-16 单位计数。
合同层验证不等于 MCP 生产路径已接入。
免费独立 App 验收、真实付费视频验收、服务端生产启用、10 / 100 用户容量验收必须分别报告。
没有真实提供方或负载证据时，不把模拟服务、mock admission / idempotency 当成生产验收。

后续运行时接入还须验证：普通 `quote_only` 无上传；官方引用准备明确副作用；精确报价与审批 / 幂等绑定；
未知提交不重放收费 POST；工程切换不串；同 key 不重复任务；缺配置 / 过期 pin 在收费前拒绝。
这些条件在实现和实际验证完成后才记为通过。
