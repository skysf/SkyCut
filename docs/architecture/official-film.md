# 官方原创短片：公开镜头合同与私有配方边界

> 2026-11-04 起。生成与计费仍走 [Sky Studio 任务](sky-studio-jobs.md)，工程归属仍走
> [开着的工程](open-projects.md)。本文只记录客户端公开合同，不收录配方、选择条件或学习来源。

## 一、职责

- 当前 AI 会话负责把用户意图整理为公开故事、分镜、世界状态和声音计划。没有额外的云端分类模型。
- 官方入口只接受 `original_film` / `science_fiction` / `none`，种类限图片、文生视频、图生视频。
  不支持的题材或场景明确拒绝，不能替用户改成另一种场景，也不能把普通生成称为官方配方生成。
- 客户端只持有公开声明和不透明凭据。私有配方选择、投影、版本保留、账户和价格绑定由服务端负责。
  不把私有 profile、研究全文、原片帧、原声音或来源映射写进工程、日志、安装包或工具结果。
- 用户已有的剪辑风格和 `recipes` / `save_recipe` 保持独立，不能用它们编辑官方配方。

## 二、请求与报价

`SkyStudioFilm` 是单镜头的公开合同：当前镜头的 context、序号、修订、entry / exit / actions，
左右邻镜的完整 render、状态和切镜声明，以及共同的声音计划。字段、枚举、字符串与数组边界严格校验；
缺 context 不填默认值。客户端不内置服务端支持场景的私有选择表。

普通请求不带 `film`，保持原来的 quote 行为。官方 `POST /quote` 必须带实际的 `inputs`、
原顺序的 image references 和完整 `film`；数量占位不能代替实际资产。首帧、尾帧与多参考的角色不能互换。
官方无素材模式只允许原创图片引用；文件归属由服务端核实，归属不等于原创来源证明。

报价中的 `official_recipe` 包含不透明 `recipe_pin`、到期时间及左右 `seam_review` 指纹。
提交使用同一请求、同一实际引用、精确价格、pin 和当前两侧审查。中间镜头从 revision 1 起就必须两侧齐全。
到期、修改当前或邻镜、参数、引用、状态、声音、cut 后必须重报价和重审，不能自动填旧确认。
pin 只用来传输，不解密、不当作可编辑的配方；服务端保留版本不可用时应在收费前失败。

## 三、世界状态与声音合同

- 连续切镜的边界状态必须相同，环境底床使用同一 `bed_id`。换机位不能解释换手、物体瞬移或重演动作。
- `completed_actions` 是累计历史。当前 `actions` 只能增加尚未完成的动作，exit 必须正好等于 entry 加新增动作。
- 有意跳时间、换地点或蒙太奇必须写明理由；`reset_fields` 只能且必须列出真实改变的字段。
  完成历史不能删除，跨缝新增动作必须列在 `offscreen_actions`。
- `music`、`environment`、`foley` 是公开的协调计划，不能据此声称已生成或听验。实际音乐、音效仍走普通生成或现有音频库。
- 实际验收应基于使用的源区间、最终时间线和成片切点；提交参考图、声明状态和报价审查均不能证明输出连续性。
  声点按最终可见动作对齐，画面改变后重新检查；数值测量与真实听辨分别记录。

## 四、MCP 执行阶段

官方调用必须属于当前会话拥有的已保存工程，并进入该工程的工具队列；生成本身仍不修改时间线。
`add_clips` 负责入轨。普通生成保持原来的工程选择和无上传报价行为。
完整公开 schema 和阶段说明按需从 `get_status film_contract=true` 读取；工具清单只放简要入口，
避免整套重复状态字段挤占所有会话的清单预算。参数检查仍展开同一份 schema，运行时严格解析不会因此放宽。

1. 先单独传 `prepare_references=true`、模型和规格，有图片时一并传路径与角色。这里明确会上传所给图片，
   不生成、不报价、不预留。经原有读权限、媒体测量、模型限制及 `/uploads` 路径完成，异步结果用 `get_job` 取。
   结果给实际生效的公开 `prepared_render`，图片另有本机 `prepared_references` 令牌和实际 inputs，供当前 / 邻镜 render 使用。
   文生镜头也能无上传地准备规格；补上真实 context 即可先写权威制作计划，避免“必须先报价才知道该存什么规格”的循环。
2. 用 `save_project.production` 和当前 `expected_revision` 保存精确的公开故事 / render 图与声音计划；
   当前和邻镜的 context 均须真实声明。工程内有输出时，先按下节建立实际来源与必要帧锚点。
3. 重复原图片路径、角色与完整规格，带 `prepared_references`、`film`、`quote_only=true`。
   报价不再上传，返回 `quote_token`、有效期、精确价格和左右 `seam_review`。无图片的文生镜头可以直接报价。
   pin 只存在 App 内存，不返回给 AI，不写工程、回执或日志。
4. 阅读当前和邻镜的状态、render、cut、声音后，使用同一请求、`quote_token`、当前两侧指纹和稳定的
   `idempotency_key` 提交。不能代替调用方自动填审查，不能自动刷新过期报价再花钱。
   草稿越档批准绑定这一份完整官方请求，不复用普通模型规格的宽泛项目批准；每日硬预算照旧生效。

新提交的幂等缓存只记已经返回真实本机 `job_id` 的 `started`。`needs_confirmation` 和每日预算 `blocked`
都还没有提交、没有预留，返回后释放本次 pending 占位；用户确认或提高预算后，同一 key 必须重新核对当前
报价、双侧审查与预算，再收确认码。不能把旧问题缓存成已完成结果，也不能为了绕过旧问题换 key 重交。
已启动任务、显式准备任务和持久原单恢复仍分别复用原操作；确认码不进入语义请求摘要。

准备 / 报价缓存绑定账户、API key 摘要、已保存工程与运行代号、文件身份、顺序和角色。
异步返回及提交前再次核对，文件原地改写也算改变。模型改变可以复用未变的已上传原图，但必须重新通过
新模型限制、报价和审查。视频 frames 模式的首尾帧不计入 `reference_image_count`；两种角色仍分别进入实际 inputs。

## 五、提交回执与恢复

官方收费请求在 POST 前把提交意图原子写入 App 自己的回执目录，文件 600、目录 700。
文件名按账户与幂等 key 摘要生成；不把 key 当路径，不提供清空后重交的入口。
回执在时间线 / 工程撤销之外，撤销故事计划不能抹掉可能已经收费的证据。

持久字段限账户、工程路径、请求摘要、公开模型与规格、输出落点、预留账及原单结果 / 账单证据。
不保存完整 film、私有配方、pin、API key 或任意服务端 metadata。
已知任务号不能改写或清掉，已有结果和落盘证据不能回退；坏文件、身份不符不能当作“还没提交”。

重启或重开同一已保存工程后，带原 `idempotency_key` 和相同语义参数恢复：
有原任务号只 GET 原单，缺任务号明确报告未知，不再 POST。恢复不依赖旧内存报价或重新上传。
若已记录“本机尚未发送”或合同明确的收费前拒绝，则报告 `confirmed_not_submitted` / `charged=false`，
不能把已知拒绝重新说成云端结果未知；该 key 仍不会重放。只有丢答而无证据的提交保持 unknown。
恢复也不重新预留、退款；若无法证明崩溃前本机预算已结算，返回 `local_budget_reconciliation=pending`，
保留服务器账单证据供核对，不把本机汇总账推测成服务端实收。

只有明确未准入的合同错误才释放本机预留。`recipe_unavailable` 表示官方配置 / 保留版本在提交前不可用；
它与一般 503、网络丢答、已给 job_id 的失败不同，后几种必须按原单证据处理，不能仅凭状态码宣布零收费。
已有本机成品必须匹配回执的非空普通文件身份，不能只因同一路径存在文件就当作原成品。

账户满额后等待名额不保留旧检查的有效性。每次实际收费 POST 前都要重新核对当前账户 / key、
仍登记的同一工程、文件身份、报价有效期与取消状态；检查期间最后一次 await 之后再验同步条件。
只有没有任何受理 / 收费证据的明确满额拒绝可等待后用同 key 重试；已知 job_id 优先只查原单。
已全额退款表示净收费为零，不表示从未准入，不能据此持久化“未提交”。

## 六、工程里的权威制作状态

`TimelineState.production` 保存公开故事、完整有序镜头图、世界状态、已完成动作、声音 cue、
实际输出绑定及观察记录。通过 `save_project {production, expected_revision}` 全量验证副本后，
一次提交给本工程的撤销 / 自动保存；相同计划是 no-op，不推进版本、不增加撤销步骤。
`expected_revision` 单独出现即拒绝，二者都省略仍是普通保存；`production:null` 用 CAS 明确清空。
清空可处理版本仍可合法比较的损坏内容，不承诺恢复负数或溢出的坏版本。
新写 render 需要已显式取得的有效公开目录；存盘不偷偷联网，已有计划的读取 / 原样保存支持离线。
图中的邻镜 render、状态、bed 与 cut 必须对应实际权威镜头；改变声明时本镜修订准确加一。

`get_timeline.production.plan` 是可回传的作者输入，`expected_snapshots` 与 `readiness` 是只读派生值。
`output_binding` 绑定实际 UUID、源文件身份和使用几何；同 UUID 换源 / 裁切 / 移动 / 变速后，
原样保存保留旧 binding，必须显式回传当前 `expected_snapshots.output_binding` 才能重新绑定。
新选 clip_id 也不刷新旧观察。邻镜变化只废掉受影响接缝，未改本镜的源观察保留。
撤销恢复完全相同的旧媒体和声明可以恢复匹配证据；降低版本号不能认证不同内容。

输出观察包含早段 0/.25/.5/1/1.5/2 秒、实际用尾 1–2 秒、每个新增动作的转折和两侧合成接缝。
请求按工程全局帧格裁入半开使用窗；动作样本至少跨一工程帧、映射到两个可用帧位置。
这些是调用方已观察的声明，不是解码 actualTime 或机器动作识别；预检 seam_review 不替代输出观察。

合成身份复用 builder 的排序 / 转场展开与 `TimelineRenderSize`，纳入实际借入画面、窗口内可见叠层、
字幕和有效样式、实际画布尺寸。短中镜尾部出现第三镜借头时，第三镜变化也使该接缝过期；
auto 画布受远处首镜尺寸影响，不能只比较 `.auto` 枚举。
声音 cue 记录层次、注意目标、覆盖镜头、时间 / 时长、对应新动作或有目的静音及恢复点。
对齐身份复用 `AudioEngineConfig` 的实际段落窗和 gain points，包含转场借音、静音、场景、曲线及推子。
元数据路径不运行声音场景补偿测量，只绑定完整场景参数；占位值不代表已测响度。
`measured_note` 与真正听辨后的 `listened_note` 分开，数值证据不自动变成听觉判断。

### 原生帧锚点与历史输入

`freeze_frame.source_frame` 保留原生 requested / actual CMTime 的整数、标度、epoch、flags、
漂移、量化容差与回退，以及抽帧前源窗、源文件 / PNG 身份。`upright_source` 是摆正后的原片，
不含上层画面 / 字幕；最终接缝仍须 `look` 时间线合成。旧 freeze 缺少原生 metadata 时不能事后补写。
来源 metadata 可回传且没有签名；时间 / 文件 / 角色一致不等于不可伪造凭证或自动视觉认证。

`expected_snapshots.shots[].source_geometry` 回读准确的源路径、in / out / duration、速度、摆放、fps，
以及 `first_project_time` / `last_project_time`。它们是共用全局帧格的请求位置，不能称为已解码 actualTime；
静图返回 null。不得从普通摘要的三位小数反推精确用窗。若 in / out 无法逐位重建原 duration，
scratch 流程应明确拒绝；仅在准入允许的自有源上，可定格后单步 undo 恢复并核对原窗，再使用保留 PNG / metadata。
转场保护等导致定格不准入时不能绕过，也不能改 metadata 或放宽半开窗来凑锚点。

已绑定来源的帧模式再次报价时，first 来自 previous.last_used 或 current.first_used，last 来自
current.last_used 或 next.first_used。实际 PNG 必须对应当前引用准备角色文件和上传 originals URL。
无输出 bootstrap 与模型没有的角色不凭空增加要求；初版不伪造静图的原生视频时间。
输出替换后保留历史 anchors，不偷偷改 render.inputs。`input_anchor_current` /
`needs_refresh_for_regeneration` 与 `output_observations_current` 分开；新输出可以已观察，而旧生成输入需要重抽。

计划不保存 pin、准备 / 报价令牌、密钥或私有配方 / 来源。收费回执在撤销之外；已知任务只 GET、
未知无号禁止 POST、明确未提交的 key 退休。恢复先于当前计划校验，清空或改剧本不能阻止查原单。

## 七、验证与状态口径

纯值与假 HTTP 回归接入 `scripts/check-sky-studio.sh` 的 `FilmChecks` / `OfficialQuoteChecks`：
严格字段、显式 context、动作累计、双侧邻镜、精确 cut、原创图片 URL 与首尾角色、报价和提交同一输入、
缺官方回答不能退到普通生成、pin 有效期 / 当前双侧指纹，以及 film / 引用 / pin / 审查变化使审批身份失效。
提示词长度与服务端一致：先去首尾空白，再按 Unicode scalar 计数；状态短文字按 UTF-16 单位计数。
合同层验证不等于 MCP 生产路径已接入。
免费独立 App 验收、真实付费视频验收、服务端生产启用、10 / 100 用户容量验收必须分别报告。
没有真实提供方或负载证据时，不把模拟服务、mock admission / idempotency 当成生产验收。

运行时回归另由 `OfficialPreparedChecks` / `OfficialReceiptChecks` 和
`scripts/gui-smoke/sky-studio/official.py` 覆盖：显式引用准备、精确报价与审批 / 幂等绑定、
未知提交不重放收费 POST、工程与账户隔离、同 key 不重复任务、缺配置 / 过期 pin 在收费前拒绝。
后台验收使用独立测试 App、假服务与合成素材，实际导入、生成、检查及导出均经 MCP；
不得以这些通过项代替真实提供方输出的画面验收。具体结果见
[实施报告](../reports/2026-11-04-official-film-client.md)。
