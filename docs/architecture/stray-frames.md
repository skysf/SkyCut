# 夹帧提醒与成片逐帧扫

> 已生效的长期约束（2026-11-16 起，`production-feedback.md` 的 MCP-36、MCP-64、MCP-65）。
> 用户定：这类检查 SkyCut 自带、**只报不拦**；放素材时**只提醒，不自动收**。成片检查本身的合同见
> [成片疑点检查](finished-video-inspection.md)；look shots 的分镜头见 [AI 接口（MCP）](ai-control-mcp.md)第四节第 29 条。

## 一、为什么

南极预告片第二稿第 2 个镜头用一条生成的素材，入点 1.95 秒、出点按「3.5 秒」整数算到 5.45 秒，过了素材自己在第 129 帧
（5.375 秒）的一刀，成片 0:07.22–0:07.30 夹了 2 帧停车场的黑轿车。用户一眼看出来，两稿都没查出来：出点按整数秒算、
没有检查拿入点出点去对素材自己的刀、隔几格抽帧和看缩略图都会漏一两帧的东西。生成的素材常自带切点（那一批 39 条里 16 条，
一条最多 5 刀，刀前后有时只差几帧）。

## 二、一套量法：逐帧小信号

- **一个文件只解一遍。** `AIShotScan` 把视频从头解到尾，每帧让解码器直接缩到长边 48 像素的 RGB，`AIFrameSignals` 记四样：
  和上一帧的平均差（`changes`）、平均亮度、暗像素占几成（亮度 ≤ 16）、画面从这一截开始到这一帧动没动（`held`：和上一帧差得少
  还不够，还要和这一截的第一帧比，慢推近、慢摇一攒够就换锚）。和 look shots **同一次扫描、同一份缓存**（路径 + 大小 + 修改时间），
  读取在 `MediaReadQueue.shots` 上（[阻塞的媒体读取](blocking-media-reads.md)）。
- **逐帧的刀只有一份：`AIShotDetector.hardCuts`**，夹帧提醒和成片逐帧扫都用它。look shots 的 `cutIndices` 为了把文件分成看得清的
  镜头，两刀之间至少 0.6 秒、片尾半段不切 —— 恰好把「刀前后只差几帧」「开头三帧是另一个画面」滤掉，所以不能拿它查夹帧。
  逐帧的刀不设这两条，只问这一帧比附近突然大多少倍，**拿中位数比**：两刀挨着时另一刀不会把基准抬上去。

| 门槛 | 数 | 出处 |
| --- | --- | --- |
| 一刀：和上一帧的平均差 | ≥ 15 / 255 | 预览板 v1.2 |
| 一刀：比前后各 6 帧平均差的中位数（加 1 / 255）高出 | ≥ 3.5 倍 | 预览板 v1.2（板上的记录：已知的刀最小 4.8 倍，别的帧最大 2.3 倍） |
| 夹帧：两刀之间、片头到第一刀、最后一刀到片尾的一截 | 不到 8 帧 | 预览板「头尾不到 8 帧的段一律报」 |
| 闪白：亮度一帧涨上去，又在 0.4 秒内落回 | 涨 ≥ 18 / 255，落 ≥ 12 / 255 | OpenFilm 给的数（只照思路，代码自己写） |
| 不动：和上一帧差 / 和这一截第一帧差 | < 0.35 / 255、< 0.5 / 255，连着 6 秒以上 | OpenFilm 给的数 |
| 黑场：亮度 ≤ 16 的像素 | ≥ 99.5%；贴着片头片尾、不到 0.5 秒的算淡入淡出 | SkyCut 原来的黑帧判法；淡入淡出照 OpenFilm |

数是照上面的出处取的，**拿合成测试片核过，没拿南极素材调**。`scripts/check-video-inspection.sh` 每次打印 `MEASURED` 两行：
合成片上的刀最小 107 / 255、15 倍，别的帧（一直在动的测试图）最大 9.5 / 255、1.2 倍，离门槛两边都远。编码出来的静止画面
（I 帧刷新）帧间差最大约 0.14 / 255，在「不动」的门槛以内。真素材上会不会误报只能实机看（第七节）。

## 三、放素材时提醒（add_clips、edit_clip / edit_clips）

- 落地之后看每段用到的源范围（`AISourceCuts`）：范围里的刀把它分成几截，每截露几帧（一帧的**大半**在范围里才算露出来：出点贴着刀、
  差几微秒不算跨）。几种：头一截 / 末一截不到 8 帧（夹进来的一小段，建议把入点 / 出点收到刀上）、两刀之间不到 8 帧（素材自己闪了一下，
  收入点出点去不掉）、刀两边都够长（一段里有两个镜头，可能就是想要的；范围里只有这一刀时建议留长的一边）。
- 结果里加 `source_cuts`：哪一段、刀在素材的第几秒第几帧、在时间线的哪一刻、刀前刀后各露几帧、建议的入点或出点、一句为什么；
  夹进来的一小段排前面，最多 8 条（多的报个数）。**什么都不改**：入点出点照 AI 给的。edit_clip 只在给了 `source_in` / `source_out` /
  `file` 时查（`AISourceCutCheck.movesSourceWindow`）。
- 不能干等：没扫过的短素材（≤ 120 秒，`AIShotScan.quickScanSeconds`）当场扫，一次调用一共最多等 10 秒；长的放的时候不扫（一扫几十秒，
  还占着唯一那条扫描队列），没扫到的列进 `source_cuts_unchecked`。交片前 inspect_video 不论长短都扫。
- 只看有画面的视频段：纯声音、图片转的静帧、还在转的图片没有「素材自己的刀」。

## 四、交片前：inspect_video

- **给了 file：整个文件每一帧都扫**（`AIFrameScan`）：`stray_frames`（不到 8 帧的一截；很暗的一截归黑场）、`flash`（已经算成夹帧的
  不重报）、`frozen_picture`（画面上只有图片、定格这类静帧时不报）、`black_frame`（连着的一段一条，写多长）。点名 from / to 时只报那一段，
  不点名报整个文件（默认范围是声音的接缝，夹帧可能在任何一段的头尾）。扫到了，黑场只用逐帧的那一份；没扫完（最多等 180 秒）照实进
  `limitations`，扫描接着跑、进缓存。结果的 `frame_scan` 写扫了多少帧、哪一段。
- **每段看得见的画面对着它的素材**（时间线和成片两种都查）：上一节的头 / 末 / 中间不到 8 帧的那几截报 `source_cut`（带
  `source_frame` 和建议的入点出点）；刀两边都够长的不报（放的时候提醒过）。素材最多等 90 秒，没扫完的进 `limitations`。
- 没给 file：画面只能抽帧（每 0.5 秒），连着几帧都黑的合成一条；一两帧的东西照旧可能漏，所以交片前用导出的文件查。

## 五、查的成片比工程旧（MCP-65）

`AIInspectionFreshness`：比文件的创建时间（导出开始写的那一刻；SkyCut 导出从不覆盖，每次是新文件）和工程最后一次改动。工程不记改动的
时刻，只记存盘：改了以后 2 秒自动存，所以有没存的改动 = 就在这几秒里；存好了，最后一次改动不早于存盘前 3 秒。确定工程在文件做出来之后
改过，就在结果里加 `attention`（键按字母排，排在最前面），开工那一下的回答和 get_job 的结果里都有，叫 AI 重新导出再查。
判断不了的不说：没存过盘的工程、存盘和文件只差 3 秒以内。改行高这类不改画面、但也会存盘的，会让它多说一句（宁可多导一次）。

## 六、没做的、以后做的

- **「故意」的标记**（标了以后不再报）：要存进工程、牵扯格式版本，归以后「交片前检查」那件做。建议的存法：工程里加一张表，每条记疑点
  种类、片段 id、素材的帧号（素材的刀）或时间线的时间范围（成片的那几种）、谁标的；检查时同一处不报，结果里报「标了故意的有几处」；
  片段被改了入点出点、换了文件，那条作废。
- 叠化认不出来（同 look shots）；剪辑软件里拖入点出点时在刀上吸一下的界面不做（这次不改界面）。
- 时间线快照不逐帧扫：每一帧都要合成，太慢；时间线上的夹帧靠每段对着素材的刀查。

## 七、守卫与回归

`scripts/check-video-inspection.sh`（`check-all.sh` 第一组）现做两条合成片：`cuts-source.mp4`（第 129 帧从会动的测试图切到彩条）、
`scan-film.mp4`（夹 2 帧、9 帧闪白、7 秒不动、1 秒黑，带正弦音）。

- `checks/VideoInspection/FrameSignalChecks.swift`（纯值）：`held` 怎么换锚、暗像素、逐帧的刀（挨着的两刀、贴着头尾、快摇不算、噪点不算）、
  成片四种疑点、`AISourceCuts` 的几种截法（南极那一条的数：末尾 2 帧、建议出点 5.375；早两帧什么都不报；出点多一微秒不算跨）、成片比工程旧的判法。
- `checks/VideoInspection/StrayFrameChecks.swift`（真文件、真工具）：真解码路径只找到第 129 帧那一刀；add_clips 提醒、入点出点照旧；早两帧不提醒；
  edit_clip 挪出点过刀又提醒、只改别的不提醒；时间线快照报 `source_cut`；给了 file 时四种疑点的时间对、`frame_scan` 扫满 393 帧、点名范围只报里面的；
  抽帧的黑场合成一条；文件比工程旧时 `attention` 排在最前面，新写的文件不说。

反向验证（2026-11-16）：五处一起弄坏跑一遍，14 条红，各自红在自己的断言上；逐字恢复后转绿。

| 临时弄坏 | 红了 |
| --- | --- |
| add_clips 不调 `AISourceCutCheck.note` | add_clips 的提醒 |
| 逐帧的刀退回 look shots 的口径（前后各 2 帧、取平均） | 挨着的两刀、贴着头尾的刀、2 帧的一截被当成闪白 |
| 不扫成片 | 夹帧、闪白、不动、黑场、`frame_scan`、点名范围 |
| 不写 `attention` | 开工的回答和结果的开头 |
| 抽帧的黑场一帧一条 | 逐帧扫的黑场和抽帧的黑场各一条 |

人工回归（发版前实机）：

- [ ] 一条自带切点的真素材（生成的那种）放上时间线、入点出点跨过刀：`source_cuts` 的帧号和 look shots=true 看到的对得上；早两帧放不再提醒。
- [ ] 真 AI 剪的成片（有闪白转场、定格、黑场、快切）用 file= 查：报出来的每一处人看过说得清是真问题还是故意；屏幕录制的教程里
  `frozen_picture` 多不多（静止的幻灯片会报）。
- [ ] 导出 → 挪一刀 → 查那个文件：结果第一行是 `attention`；重新导出查新文件没有。
