## 第一刀：公开合同

- `SkyStudioFilm` / `SkyStudioFilmReader` 只验证公开故事声明；不猜服务端私有支持范围。
- `SkyStudioFilmInputs` 保住实际原创图片输入、顺序和首尾角色。官方 quote 带真实 inputs；普通 quote 保持原格式。
- `SkyStudioOfficialRecipeQuote` / `SkyStudioSeamReview` 保留不透明 pin、有效期和双侧指纹。
  缺官方报价回答时失败，不退到普通生成。修订 1 的中间镜头也要求左右两侧。
- `SkyStudioApproval` 对官方请求把 film、引用、pin、当前审查和价格绑定；普通请求身份保持原样。
- 审查中修正了提示词长度的跨语言差异：与服务端相同，裁掉首尾空白后按 Unicode scalar 计数。

`generate_media` 复用原模型目录、上传器、审批 / 预算、任务、下载与可编辑副本管线。
`get_status film_contract=true` 按需返回完整公开合同；工具清单保持既有 100,000 UTF-16 预算。
准备阶段给出实际 `prepared_render` 和原图资产；报价不上传、不预留；提交保留同一请求、价格、pin 与两侧审查。
账户 / key、工程、文件身份、角色、顺序及请求改变都会使旧准备或报价失效。

官方请求在收费 POST 前持久保存最小恢复回执。已知原单重启后只 GET；未知且无任务号保留未知、禁止重交；
明确未准入则保存 `confirmed_not_submitted`。本机预算不能原子证明已结算时保留 pending，不二次扣退。
回执在工程撤销之外，不含 film、pin、私有配置或凭据，任务号、退款和结果证据不能回退。

确认流程修复前，`scripts/check-all.sh` 五组共 82 项全部通过；清理隔离修复后的完整 MCP 3,178 项通过。确认修复后再跑全量，第 1 / 2 / 3 / 5 组全部通过，第 4 组的 MCP 检查发生原生 SIGSEGV，不能计为全绿。崩溃报告确认短窗音频读取与外部 `cancelReading` 并发，违反 SDK 约束，将独立修复后重验；隔离阶段日志与 arm64 调试器运行的 3,178 项通过只作为定位证据，不代替失败的统一入口。推前 `check-guards` 全绿。早先的空闲 watchdog 113.5 ms 超过 100 ms 门槛，随后该组单独及新全量均通过，不将首次失败记作通过。

提交前复审发现确认 / 硬预算结果被误缓存为已完成，导致同 key 无法兑换确认码或在预算恢复后继续。旧 linked App 的后台 MCP 反向准确失败；修复后只缓存真实 started 任务。新增预算闸 / 确认码 / HTTP 联动检查，隔离撤掉筛选后 1,441 项中 15 项失败，撤掉生产接线后 2 条守卫失败。

后台 MCP 实际执行以下 13 组：

1. 自有无窗口工程；第二 helper 不能读或抢占活动工程。
2. 文生镜头准备返回生效规格，零上传 / 报价 / 任务。
3. 原始首尾 PNG 真 PUT 上传一次；官方报价绑定实际 originals URL 和双侧审查。
4. 两侧缺失 / 过期审查、请求、令牌、角色、工程和文件变化均拒绝。
5. 等待名额期间原图身份改变，下一次 POST 前拒绝、释放本机预留，并将该 key 留为不可重放。
6. 缺配方、错误 context、过期报价及报价后收费前拒绝，均无提供方任务。
7. 同 key 经过待确认、错码拒绝、正确确认后只提交一次；后续重复调用仍返回原任务。
8. 同 key 被硬预算阻止后，经模拟用户明确恢复假账户预算，重新核对并只提交一次。
9. 提交只用原价格与 pin；同 key 一次 POST，新 key 不能复用已消费报价。
10. 经 MCP 导入、双侧接缝抽帧、数值声音测量、导出和成片抽帧。
11. 丢答与下载失败保留原单，不自动重生成。
12. 换账户不能复用另一账户的内存令牌。
13. 重启后已拒绝 key 保持零收费，未知 key 禁止 POST，已知任务号只 GET 原单。

## 验收后续：原生音频读取取消

原生崩溃栈及本机 Apple SDK 确认 `cancelReading` 与 `copyNextSampleBuffer` 不得并发。
独立修复让 analysis 同步读取体单点取消 / 释放，外部只发停止信号；排队与 metadata 取消仍分阶段处理。
独立读取检查 49 项通过，安全的旧代码反向 10 项中 5 项失败；没有为制造红灯触发原生并发崩溃。
并行构建时的 2 秒成功路径超时与 15 秒 watchdog 均保留为失败，未放宽阈值。独立第 4 组已完整通过（6 / 0，其中 MCP 3,188 项通过），本地五组共 82 项均已完成；完整 App 已重新链接，推前守卫全绿；独立 PR 的 GitHub 汇总结果另行核对。
见[取消 listen 时跨线程拆掉正在读的 reader](../bugfixes/2026-11-04-listen-reader-cancel-during-copy.md)。
