# SkyCut MCP 发现与真实 Codex 选工具实测

本次把“App 有能力”“helper 列出定义”“客户端把定义交给模型”“模型实际调用并完成任务”分别验证。
前两项改动见 [PR #290](https://github.com/skysf/SkyCut/pull/290)（发现诊断与重连）和
[PR #291](https://github.com/skysf/SkyCut/pull/291)（需求目录、最小示例与正确参数提示）。
原始结果的归一化摘要在[调用证据 JSON](2026-11-03-mcp-discovery-evidence.json)：保留实际工具名、参数、任务结局、
检测疑点和落盘断言；临时路径替换成 `$SCRATCH`，不含用户原工程路径或生产 Key。

## 环境与隔离

- Codex CLI **0.166.0**，沿用用户已有的 **GPT-6.1-Sol / max**，没有为测试另选模型。
- 自然语言测试连接独立 `com.srtflow.SrtFlow.skystudiosmoke` App、回环假 Sky Studio 和合成素材；没有 Sky Studio 付费生成。
  其他 MCP 仅用本次进程的 `-c ...enabled=false` 关闭；用户配置文件未改。
- 四个独立工程各有两段 2 秒、640×640 / 24fps 画面、两处 40 号标题和一段裁到 4 秒的旧旁白。
  新旁白是本机 Samantha 合成的英语，实测 **2.443492063492 秒**；旧录音文件全长约 7.33 秒。字幕轨为空。
- 实测版工具清单 55 项，JSON 99,811 字符、统一说明 1,948 字符，指纹 `e800b313aadd39b5`。
  实测后仅补回 `get_status` 的任务分组文字：最终 JSON **99,829** 字符；全部 55 个参数 schema、六个重点工具定义
  与实测版本逐项相同。工具数是本次观测值，生产实现从真实清单计算。
- 已安装 App `0.18.56-local.20261102.2247.g0207d5f` 另建后台临时工程补测工具包装层；原工程前后 SHA-256 相同。
  测试工程均保存并关闭，隔离 App 和假账号清理完毕；没有替换用户安装包或发版。

| 路径 | 实际结果 |

| 结束旧 CLI、改用当前 helper，resume 同一测试对话 | 握手后重新取 55 项 / 9 参数；自然语言批量标题实际调用新增 `set_texts`，随后同一对话用新增 `preset=quick_review` 导出完成 |

旧版导出缺的是 `preset`、`encoder`、`quality`；原有 `resolution` 一直存在。
历史 helper 的显式重列测试确实导出完成，但无音频夹具的检查结果 `coverage_complete=false`，不据此认证成片质量。
包装层补测的含音频工程检查则返回 `coverage_complete=true`，并完成硬件 / AAC128 / 480p 的覆盖参数导出。

本机 CLI 的复现定位到客户端缓存：helper 已采用 App 定义、通知也确实送达，客户端没有重读。
原用户旧会话没有完整传输日志，无法进一步判定它当时是未收通知还是未采用；未对原用户图形会话强制重启。
没有发现当前服务端或包装层把清单硬截在 50 项。

另有一条独立的客户端提示：CLI 忽略旧 `mcp.remote_mcp_client_enabled` 配置节，每次启动报告两遍。
有效的 `mcp_servers.skycut` 连接仍正常发现并调用 55 项；该提示不解释本次通知后的缓存行为，用户配置未改。

| 导出审阅版：快速、小一些，不改正式设置 | **`export_video preset=quick_review`**，`get_job wait_seconds:30`；又检查输出文件；共 13 次调用 | MP4 实际存在：硬件 H.264、Q45、AAC128、720p 短边上限；源 / 画布 / 输出均为 640×640 / 24fps，未升采样；正式导出偏好键前后相同，工程时间线不变 |

## 重连旧对话的新增参数补测

在原先 50 项的同一个合成测试对话中，继续提出“导出审阅版，快速、小一些，不改正式导出设置”。
该对话没有换历史记录或模型；最终版清单指纹为 `c5a2619ff650fe76`，仍为 55 项 / 9 个导出字段。

第一次与显示初始界面后的第二次尝试，分别有 4 次、2 次 `export_video preset=quick_review` 调用被 App 拒绝：
“video engine is not ready”，没有创建任务。模型明确报告失败，不能把选对参数当作导出成功。
当时重新组装的测试 App 未带视频引擎，启动覆盖路径指向 Downloads 中的仓库；仅显示界面没有恢复。

把同一份 `vendor/ffmpeg` 复制到本轮临时目录、显式指定该路径并只重启测试 App 后，
继续同一测试对话，**11 次 MCP 调用、一次 `export_video preset=quick_review`，`export-1` 为 done**。
实际文件独立完整解码通过，硬件 H.264 / AAC128、640×640 / 24fps；时间线与对照相同，正式导出偏好键仍未写入。
路径调整与成功有直接观测，但本次没有定位具体系统拦截原因，不把前六次拒绝归咎于客户端缓存或声称已修复引擎初始化。
这三轮及其失败消息均在证据 JSON 的 `resumed_export_followup` 中保留。

## 自动转写失败与有效恢复

换旁白和接缝检查里各额外发起一次 `transcribe language=auto`，任务 **`transcript-1` / `transcript-6` 均为 failed**。
返回原因是无法判断所说语言，建议语言已知时明确传入。MCP 调用本身完成、进程退出 0，不等于转写成功。
这两次失败保留在证据里；同步与声学检查的主链没有依赖这份转写。

继续同一个接缝检查测试对话，补充“这两份旁白都是英语，请用明确英语设置重试，不改剪辑”。
Codex 用 `transcribe language=en,words=true` 重试两份文件，实际任务 **`transcript-10` / `transcript-11` 均 done，返回 `en_US`**；
随后读取缓存结果，时间线仍与对照相同。不能把这个结果写成自动语言检测已修好；本次未定位检测器判不出的内部原因。

这批自然语言夹具验证了画面 / 标题按旁白时长同步；字幕轨为空，字幕逐词重新对齐仍走其专门自检和人工回归。

## CI 暴露的共享导出进程收尾问题

说明 PR 的 CI 连续两次在已有矩形取景导出检查超时，第三次加原生采样后定位到
`FFmpegProcess.waitUntilExit()` 的跨线程 RunLoop 等待；两条输出管道已经结束，并非卡在读取输出帧。
这一问题由独立 [PR #292](https://github.com/skysf/SkyCut/pull/292) 修复：启动前注册退出回调，
与两条管道的排空汇合；启动失败也解除回调、关闭写端并归还计数。

新增守卫实际跑 128 次串行和 32 次并发立即退出、双管道大输出、错误及取消，连同既有导出检查共 39 条通过。
临时撤掉修复，同一守卫在串行立即退出阶段卡住并于 30 秒后退出 1；恢复后，取景矩阵 223 条和完整本地 82 项均通过。
具体证据和长期约束见[进程退出案例](../bugfixes/2026-11-03-ffmpeg-exit-wait-runloop.md)。
此修复不改 MCP 清单、说明或参数 schema；六个重点工具的定义与参数合同保持不变。

## 有效刷新步骤与后续回归

已实测的 CLI 恢复：保存工作，结束旧 CLI 进程，确认连接指向当前 App 中的 `skycut-mcp`，
再启动并 `codex exec resume <测试会话 id>`。同一测试对话实际重新发现并调用了新工具。
仅重开 SkyCut、等一分钟或在旧对话里说“重新列工具”，均不能保证模型定义更新。

桌面 / IDE 客户端按[分层发现与重连指南](../architecture/mcp-discovery.md)重启 MCP 连接或客户端、再新建会话；
该操作流程依据官方入口说明，本次没有认证每个图形客户端旧会话都支持热刷新。
真实客户端的重测方法进入 [GUI 冒烟流程](../testing/gui-smoke-testing.md)；模拟 helper 客户端的清单测试仍不能替代模型调用。
