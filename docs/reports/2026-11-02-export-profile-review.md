# 导出耗时与快速审阅实测

使用 104.133 秒、1920×1080、30fps 教程的独立副本，素材一起复制到 `/private/tmp`，
不在用户已打开的工程上执行。原工程 SHA-256 为
`9d59a6df934866118542ba76868ba52892777d3d76719cb3c8cdbd4858779ecd`。
只运行链接真实 App 对象的隔离检查/测量进程，未打包、安装或发版。

## 基线与诊断

原正式默认：libx264、CRF 23、slow、1080p、AAC 192 kbps。本次实测总长 620.735 秒，
计划/准备 18.111 秒，ffmpeg 602.624 秒；107 路输入。未复现历史 879 秒的精确值，
本次比较只使用同一副本与本机这次的实测，不把历史数据当对照基线。

静止 PNG 用输入循环铺满整片，造成重复解码；修复与长期约束见
[案例](../bugfixes/2026-11-02-export-redecodes-static-overlays.md)。
计时口径、参数覆盖和快速审阅的确定设置见
[导出设置](../architecture/export-settings.md)。实际计时为生产 `VideoEditExportGraph.plan` + `FFmpegProcess` 的完整调用；没有排队。
`get_job` 的任务、排队和取消接线另由隔离生产对象自检覆盖。测量入口使用 arm64 调试对象，
ffmpeg 为仓库同一份生产二进制；这些数字不宣称等同于所有机器/构建的耗时。

| 优化后正式 | 117.728 | 99.309 | 14.251 | 1920×1080 / 30fps | 4711004 | CRF 23 / slow |

正式默认不变：总耗时缩短 81.0%（5.27 倍速度）。

本次正式前后两份 MP4 **逐字节相同**，SHA-256 都是 `e7929ecb7b56b3b540e7bd429b8752a4ae940fe8afc44f839ee9530f598da8f0`。
不仅抽帧或视觉近似：这个样本的画面、声音和容器也完全相同。
实际文件容器时长均约 104.110 秒，时间线为 104.133 秒；优化保留了原导出的结果。

正式优化后的其他阶段：准备 0.072 秒，文字/形状绘制 3.914 秒，
图组装 0.026 秒，交付清理 0.157 秒；
此工程没有需要 AVFoundation 中间片的画面动画，因此 prerender 为 0。

## 限制

- 硬件质量数值与 CRF 不是等价指标；速度提高不保证文件更小。本例硬件 1080p 约 15.66 MB，
  审阅 720p 约 6.75 MB，软件正式约 4.71 MB。审阅是明确的较低交付规格，不写回正式设置。
- 快速审阅仍按工程画布合成，最后缩到 720p，以保住字体/形状布局；复杂合成依然有成本。
- ffmpeg 的阶段包含解码、滤镜、编码和封装，无法据其合并时间单独给编码器定罪；
  此次 PNG 原因另用真实解码计数守卫证实。
- 本机没有模拟排队；实际排队由任务自检控制占道后验证，不以假的预计时间替代实测。

用户原工程在实测前后 SHA-256 一致。

## 专项验证

- `scripts/check-export-profile.sh`：25 条断言、0 失败；真实 get_job、排队及排队取消、
  正式/审阅实际文件尺寸与编码参数、用户设置和工程不变、阶段总和、实际 AVFoundation 预渲染计时。
- 回归守卫从真实 ffmpeg 日志查 PNG 解码帧数。临时恢复旧 `-loop 1` 接法后，
  同一个两秒夹具的静态 PNG 解码 **53 帧**，两条守卫变红（25 条中 2 失败）；
  恢复优化后为 **1 帧**，全部 25 条通过。
- MCP 自检 3,076 条通过，工具清单仍在 100,000 字符以内。
- 全片 SSIM 为 1.000000；前后正式 MP4 的 SHA-256 一致是更强的逐字节证据。
