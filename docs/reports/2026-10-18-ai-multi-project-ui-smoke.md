# AI 多开补测：屏幕亮着把界面那几项走一遍（测试版 0.18.42 → 0.18.45）

> 2026-10-18。[AI 多开方案](../plans/2026-10-17-multi-project-ai-editing.md) 四刀（#224–#240）的四轮冒烟都是屏幕锁着跑的，要看界面的几项留在了
> [开着的工程](../architecture/open-projects.md) 第八节和 [AI 接口（MCP）](../architecture/ai-control-mcp.md) 第八节的人工回归清单里。用户把屏幕点亮后叫补测。
> 走下来撞出三个问题，各修一个 PR（#241、#242、#243），修完出测试版复测。

## 测试版

- 起点是第 ④ 刀的 0.18.42（树 = main 7971da7）。修完各出一版：0.18.43（#241 + #242，树 = main cdbb681）、0.18.44（#243 第一版）、
  0.18.45（#243，树 = main c678ef8）。都在干净的 worktree 里 `VERSION=… scripts/build-app.sh` + `scripts/build-beta-app.sh`；每一版验包：版本号 / arm64 /
  `codesign --verify --deep --strict` 过 / 证书 leaf 76d27565…（和 `packaging/signing-identity.sha1` 一致）/ 打包日志里没有 ad-hoc 的退路 /
  小程序 `SRTFLOW_MCP_NO_LAUNCH=1` 喂 initialize 能答。装之前退掉旧的测试版，原地 `rm -rf` + `ditto`；只换测试版，正式版没动（0.18.37）。

## 怎么测的（用户同时在用这台电脑）

- **AI 一直是同一个会话**：一个常驻的小脚本起测试版里的 `srtflow-mcp`、握手之后在本机 socket 上收调用、一条条转过去 —— 同一个小程序 = 同一个会话，
  中间随时能去界面上点（`client.py` 是一口气跑完一张表）。再起一个 = 另一个会话（B，`clientInfo` 叫 Codex，横幅上就写 Codex）。
- **点界面不动鼠标**：按钮、菜单项、窗口的关闭按钮用辅助功能的 `AXPress`；按窗口号截图（`screencapture -l`）；窗口在不在、谁在最前看 CG 的窗口列表
  （屏幕亮着时它是准的）。侧边栏的按钮在主窗口里，主窗口被工程窗口挡着时按坐标命中会落到挡在前面的窗口上 —— 要沿着侧边栏的 `AXOutline` 找到那个按钮元素再按。
- **要按键的几项**（⌘Z、空格、⌫、打字）：发给后台 App 的按键没人接（测试版启动后从没被激活过、没有键窗口；没验证过的菜单项也是灰的），只能把它切到前台。
  做法：等用户键盘鼠标空闲 3 秒 → 摆出目标窗口、切前台 → 按键只用 `postToPid` 发给测试版 → 马上切回用户原来的前台 App。
- 素材在 scratchpad：Alpha / Beta 两个文件夹各一条 4 分钟的 1080p 测试画面（导出够长、看得到进度）和一段 `say` 念的英文（生成字幕、翻译有人声可认）。

## 撞出的问题

1. **侧边栏「AI 在剪的工程」只有标题、工程那几行从来没出来过**（第 ③ 刀 #235 引入）：这一节套了 `.equatable()` 挂在 List 里，List 把它当成一行、
   里面的 Section 只画出标题；后台工程在界面上看不见、停不了、关不掉。修复 #241，[案例](../bugfixes/2026-10-18-ai-projects-sidebar-rows-never-shown.md)。
2. **别的工程的导出显示在每个工程窗口里，还能从这里停掉**：导出器全 App 一个，p1 的面板里显示 p3 的 AI 导出进度、导完挂着 p3 的成片，
   每个窗口的预览条上都有停止键、停的是别的工程。修复 #242，[案例](../bugfixes/2026-10-18-export-progress-shown-in-every-project-window.md)。
3. **侧边栏那一行默认宽度下看不到百分比，排队的也写「导出中」**（行出来之后才看得见）：修复 #243，
   [案例](../bugfixes/2026-10-18-ai-projects-sidebar-row-status.md)。

## 顺带看到（不是这几刀引入的，这次不改）

- 一次给 SrtFlow 两个工程文件（访达里选两个双击）只开第一个：`application(_:open:)` 用的是 `urls.first(where:)`，单工程时代的写法。
- 横幅「Claude made 1 changes.」单复数不分。
- AI 的改动没登记撤销的动作名，编辑菜单上只有「Undo」，看不出撤的是什么；「撤销标题跟着键窗口变」只能看能不能点（清单那一条改成了这样写）。
- 成片的限幅提示「went over -1 dBFS for 0.00 s」：压的时长不到 5 毫秒时写成 0.00 秒。
- 测试工具上的坑（都记进了 [GUI 冒烟流程](../testing/gui-smoke-testing.md) 四之五）：App 不在前台时开着导出面板（sheet），它的辅助功能树会退化
  （窗口列表、按坐标命中都只回到 App 本身），面板关掉就好；这时用 AppleScript 让它退出会被拦下（「User canceled」）并顺手关掉面板、把 App 切到前台。
  换测试版后起常驻会话时没等 socket 能连上就发，前几个调用落空，后面一个没点名文件夹的 `new_project` 建到了「下载/SrtFlow/Projects」——
  那个文件夹和工程都是那一刻建的，让 AI 关掉工程后删了，「下载/SrtFlow」回到原样。

## 用户离开电脑后补完的三项（0.18.45）

当天稍后用户说「我现在不动电脑」，剩下要真动鼠标、真录屏的三项用真鼠标（CGEvent）补完。场景：p1 在主窗口（AI 在剪）、p2 在自己的工程窗口、p3 在后台，侧边栏是图标档。

| 项 | 结果 |
| --- | --- |
| 图标档鼠标停上去的提示 | 停在后台工程的图标上：「Menu C (p3) · Idle」；停在 AI 正剪着的工程上：「Menu B (p2) · Editing…」—— 名字、短 id、状态都在 |
| 图标档的右键菜单 | 三样：Stop / Show Window / Close Project。空闲的工程 Stop 是灰的，在剪的工程 Stop 能点；在菜单里点 Stop：p2 的图标变成停止、AI 再改 p2 被拒，p1 照改 |
| 在工程窗口里点录屏，录完落进那个工程 | 设置页弹在 p2 的窗口上；来源选「A window」→ 系统的「Share a Window」选择器里选 p2 那个窗口 → 录了 50 秒（只录那一个窗口，2360×1688）→ 停止后落在 **p2** 的 V1 末尾（talk-a 后面），p1 没变；在 p2 的窗口里 ⌘Z 一步退掉。测试用的 .mov 存在「下载」里，验完挪进了废纸篓 |
| ⌘O 的系统打开面板 | AI 正剪着主窗口的 p1 时按 ⌘O、选一个工程文件：开到**新的工程窗口**里（p4），主窗口的 p1 原样，AI 接着改照样成功 |

驱动时撞到的（不是 SrtFlow 的问题，都记进了 [GUI 冒烟流程](../testing/gui-smoke-testing.md) 四之五）：用辅助功能改了系统打开面板「前往」框里的字、
当时输入法是拼音，一按回车 macOS 的 `openAndSavePanelService` 就在输入法那一层抛异常崩掉（面板整个消失，DiagnosticReports 里三份崩溃报告）；
临时切到 US 键盘布局再按回车就正常，做完切回拼音。录制浮窗不进截图（故意的），找它的停止按钮要靠辅助功能。
